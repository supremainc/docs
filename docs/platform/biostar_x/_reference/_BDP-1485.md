h2. 1. 무엇을 / 왜

h3. 1.1 한 문장 요약

모니터링(Monitoring) 화면의 장치 상태 트리(Status Tree)에서 여러 장치를 한 번에 선택해 다섯 종 제어를 일괄로 실행한다. 다섯 종은 장치 잠금 해제(Unlock Device)·인증 실패 잠금 해제(Release Lockout)·작업 중지(Stop Action)·재연결(Reconnect)·재시작(Reboot)이다. 운영자가 직접 건 잠금은 장치 잠금 해제로, 인증 실패로 자동으로 걸린 잠금은 인증 실패 잠금 해제로 각각 별도 버튼이 푼다. 장치 하나를 선택했을 때 열리는 장치 미리보기(Device Preview) 패널에도 같은 제어 버튼과 연결 끊김 시 재연결 유도 배너를 통합한다.

h3. 1.2 사용자 가치

* 여러 장치에 동시에 발생한 알람·동작을 한 번의 작업으로 정리한다.
* 장치마다 메뉴를 반복해서 여는 번거로움을 없앤다.
* 단일 미리보기와 일괄 제어가 같은 제어 묶음·같은 권한 규칙을 따르게 하여, 화면별로 동작이 어긋나는 혼란을 없앤다.

h3. 1.3 범위

*포함*

* 장치 상태 트리(장치 탭)의 다중 선택 — Ctrl+클릭(Mac: Cmd+클릭) 개별 토글, Shift+클릭 범위 선택, 그룹 노드 클릭으로 하위 장치 일괄 선택.
* 일괄 제어 패널 — 다섯 종 제어 버튼, 선택 장치 목록 표, 실행 결과 안내.
* 단일 장치 미리보기 패널의 제어 버튼 통합과 연결 끊김 시 재연결 유도 배너.
* 이번 버전에 다섯 종 제어(장치 잠금 해제·인증 실패 잠금 해제·작업 중지·재연결·재시작)를 모두 구현한다. 단건 제어가 대부분 존재하고 일괄화 난이도가 균일해 단계를 나누지 않는다. 장치 잠금 해제는 기존 처리 경로를 재사용하고, 인증 실패 잠금 해제는 신규 API 로 처리한다(신규 API 신설 예정).

*포함하지 않음 · 후속 작업*

* 출입문(Door)·엘리베이터(Elevator)의 일괄 제어는 별도 기획에서 다룬다.
* 일괄 연결 처리 경로(백엔드)는 별도 작업으로 진행 중이며, 준비 전에는 장치별 순차 호출로 같은 결과를 낸다.
* 근태·방문자·모바일 크리덴셜과 영상 연동은 이번 변경과 접점이 없다.

h2. 2. 화면별 표시·동작

h3. 2.1 장치 다중 선택

* 운영자가 장치 상태 트리에서 장치를 클릭하면 그 장치가 단일 선택되고, 우측에 장치 미리보기 패널이 열린다.
* Ctrl+클릭(Cmd+클릭)은 그 장치를 선택 묶음에 더하거나 뺀다.
* Shift+클릭은 직전 선택과 현재 사이 구간의 실제 장치만 선택하며, 그룹 노드는 선택하지 않는다.
* 그룹 노드를 클릭하면 그 그룹 아래의 실제 장치가 한꺼번에 더해지고, 이미 선택된 장치는 그대로 유지된다.
* 다중 선택은 이 세 가지(Ctrl/Shift+클릭, 그룹 노드 클릭)로만 진입한다. 별도 선택 모드 토글 버튼이나 항목 체크박스는 두지 않는다.

*선택 장치 수에 따른 우측 영역 전환.* 우측 영역은 선택된 실제 장치 수로 갈린다 — 0개는 패널 닫힘, 1개는 단일 미리보기 패널, 2개 이상은 미리보기를 닫고 일괄 제어 패널이다. 하위에 실제 장치가 없는 빈 그룹 노드만 누르면 선택 장치가 0개가 되어 직전 미리보기·일괄 제어 내용을 지우고 우측 패널을 닫는다(미리보기 해제). 그룹 노드 자체는 제어 대상이 아니라 그 아래의 실제 장치만 제어하기 때문이다.

h3. 2.2 일괄 제어 패널

*선택 장치 목록 표.* 운영자가 패널 하단에서 선택한 장치를 표로 확인한다. 표는 이름(Name)·이상(Abnormal) 2개 열로 구성된다. 이상 열은 노드의 이상 상태(인증 실패 잠금·동기화 오류·통신 서버 오류 등)를 표시하는 라벨이다. 표시 라벨을 분류 개념과 같은 '이상'으로 하여, 같은 표를 쓰는 출입문·엘리베이터 일괄 제어와 라벨을 통일한다. 연결 상태(연결됨/연결 끊김)는 이름 옆 연결 표시등(녹색/적색)으로 표시한다. 그룹 선택으로 자동으로 더해진 장치도 한 행씩 보인다. 이 표의 연결 표시등·이상 열은 선택을 유지한 채 장치 상태가 바뀌면 별도 새로고침 없이 실시간으로 갱신된다.

*제어 5종 평면 배치.* 일괄 제어는 장치 잠금 해제·인증 실패 잠금 해제·작업 중지·재연결·재시작 다섯 종을 일반→특수 순으로 한 묶음에 보여 준다(기본/고급 2단 구분·접기 토글 없음 — 그 구분은 코드·도메인 근거가 없어 제거). 제어가 다섯 종으로 늘어나므로 버튼 묶음은 헤더·선택 목록 표와 시각적으로 구분된 패널에 두고, 화면 높이를 넘으면 그 패널 안에서 세로 스크롤된다. 제어 패널과 선택 목록 표 사이에는 구분 경계선을 두어 두 영역을 나눈다(단일 미리보기에서 제어 영역과 장치 정보 영역을 나누는 것과 같은 처리). 운영자는 이 경계선을 위아래로 드래그해 제어 패널과 선택 목록 표의 높이 배분을 조절할 수 있다(선택 목록 표 확장 — 모든 일괄 제어 화면 공통). 일괄 제어 버튼은 이 패널 도구 모음에만 둔다. 다중 선택 상태에서 트리 노드를 우클릭하면 선택 묶음용 일괄 메뉴가 아니라 우클릭한 그 노드 단독의 기존 단일 노드 메뉴가 현행 그대로 표시된다 — 기존 우클릭 메뉴가 선택 묶음과 무관하게 우클릭한 노드의 메뉴이기 때문이다(선택 묶음 우클릭에 일괄 제어 컨텍스트 메뉴를 제공하기로 했던 이전 결정을 되돌림). 장치 잠금을 새로 거는 'Lock' 제어는 일괄·미리보기 제어에 두지 않고 잠금 해제 계열만 노출한다.

*즉시 실행 + 실행 전 확인 한 단계.* 운영자가 제어 버튼을 누르면 예약 단계 없이 선택 장치 전체로 요청이 전달된다. 다만 모든 제어 버튼은 보내기 전에 표준 확인 창을 한 번 거친다. 확인 창은 액션명 제목·경고 아이콘·확인 문구·\[취소\]/\[액션명\]으로 구성한다. 다섯 제어가 모두 이 표준 확인 창 하나를 쓰며, 제목·버튼 라벨·문구만 액션별로 바뀐다 — 잠금 해제 전용 창은 없다. 확인 창은 대상 장치 수·목록을 안내하지 않으며, 대상 수는 확인 창이 아니라 제어 행 카운트로 미리 보인다. 잠금 해제 확인 문구도 그 액션을 실행할지 묻는 확인 질문 한 단락으로만 둔다. 확인하면 전송하고, 취소하면 보내지 않는다. 이 확인은 예약이 아니라 한 단계 확인이라 즉시 실행 모델은 그대로다. 대상은 버튼을 누른 시점의 선택 묶음으로 고정되며, 전송 뒤 선택을 바꾸어도 이미 보낸 명령의 대상은 바뀌지 않는다.

*제어 행 카운트 — 잠금 해제 계열 둘만.* 대상 장치 수 카운트는 장치 잠금 해제·인증 실패 잠금 해제 두 제어 행에만 붙인다. 카운트가 의미를 갖는 제어가 이 둘(잠긴 장치 수·인증 실패 잠금 장치 수를 알려 주는 잠금 해제 계열)뿐이기 때문이다. 두 잠금 해제 행은 중복 라벨 헤더 없이 카운트·실행 버튼만으로 구성하며, 대상 수가 0이면 카운트를 0으로 표시하고 버튼을 비활성으로 둔다. 작업 중지·재시작·재연결 행은 카운트를 표시하지 않고 버튼만 두며 활성/비활성만 가른다 — 작업 중지의 강제 적용 카운트는 상태 소스가 없어 보류하고, 재연결은 카운트 없이 재연결 가능(상위 장치 없는 루트이면서 서버에서 장치로 연결하는 방식) 장치가 하나라도 있으면 연결 끊김과 무관하게 상시 활성한다. 권한이 없거나 구조적으로 지원하지 않는 버튼은 비활성이 아니라 숨김으로 처리한다.

||제어(카운트 표시)||카운트 기준||버튼 활성 조건||
|장치 잠금 해제|선택 장치 중 장치 잠금이 걸린 장치 수|장치 잠금 장치 1대 이상|
|인증 실패 잠금 해제|선택 장치 중 인증 실패 잠금이 걸린 장치 수|인증 실패 잠금 장치 1대 이상|

두 잠금 해제 카운트는 잠금 종류(장치 잠금/인증 실패 잠금)를 구분하는 신규 API 의 상태로 각각 산출한다 — 현행 코드는 잠금이 단일 상태라 두 잠금을 구분하지 못하므로, 종류 구분과 인증 실패 잠금 해제 명령은 신규 API 가 제공한다(신규 API 신설 예정). 신규 API 준비 전까지는 장치 잠금 해제(기존 경로)를 우선 제공하고 인증 실패 잠금 해제는 API 준비 후 활성한다.

작업 중지·재시작·재연결은 카운트 없이 버튼만 노출하고 활성/비활성만 가른다. 작업 중지의 강제 적용(Override) 건수 카운트는 이번 버전에서 보여 주지 않는다 — 강제 적용을 장치 단위로 판정할 실시간 상태 소스가 아직 없어, 작업 중지 버튼은 카운트 없이 장치 유형·모니터링 수정 권한 기준으로만 노출한다(장치 상태와 무관). 강제 적용 카운트는 장치 상태 소스가 마련된 뒤 도입한다. 재연결도 종전의 '재연결 가능 장치 수' 카운트 표시를 제거했으나, 활성 조건은 그대로 유지한다(재연결 가능 장치 1대 이상이면 상시 활성).

*잠금 해제 2버튼.* 잠금 종류에 따라 버튼이 나뉜다. 운영자가 직접 건 잠금(장치 잠금)은 장치 잠금 해제(Unlock Device) 버튼이 푼다. 인증 실패 잠금은 인증 연속 실패나 장치 관리자 비밀번호 오입력으로 자동으로 걸린다. 이 잠금은 인증 실패 잠금 해제(Release Lockout) 버튼이 풀며, 원인은 구분하지 않고 하나로 처리한다. 두 버튼 모두 위의 표준 확인 창을 거친다. 장치 잠금 해제 대상은 잠긴 장치 상태로 산출한다. 인증 실패 잠금 해제의 대상 산출과 해제 명령은 신규 API로 처리한다(신규 API 신설 예정).

*장치 유형별 버튼 분기.* 시스템은 장치 유형과 연결 방식에 따라 제어 버튼 종류를 다르게 표시한다. 제외 대상은 장치 지원 여부를 따로 조회하지 않고 유형만으로 미리 정한다. 표의 '잠금 해제 계열'은 장치 잠금 해제와 인증 실패 잠금 해제 두 별도 제어를 함께 가리킨다 — 두 잠금 해제의 장치 유형 노출 규칙이 같아 분리 후에도 한 칸으로 묶어 적는다.

|장치에서 서버로 연결하는 방식(Device ▶ Server Connection)의 장치|작업 중지·재시작·잠금 해제 계열, 재연결(일괄 상시 제어에서만 표시·비활성, 단일 미리보기=숨김)|연결 끊김 배너·단일 미리보기에서는 재연결을 숨기고 안내 문구만 표시한다. 일괄 상시 제어에서만 재연결 버튼을 표시하되 비활성으로 두고 '서버 연결 방식 장치는 서버에서 재연결을 개시할 수 없습니다' 사유 툴팁을 단다. 나머지는 장치 유형 규칙 그대로|

여기서 '기본 장치'는 마스터와 구분되는 별도의 단독(standalone) 루트 장치 유형이다 — 마스터는 슬레이브를 거느린 RS-485 호스트이고, 기본 장치는 슬레이브 없이 서버에 직접 연결되는 루트 장치다. 둘 다 상위 장치가 없는 루트여서 재연결 가능 조건(루트 + 서버에서 장치로 연결)이 같다. '기본 장치' 표면형은 신규 다국어 키로 등록한다(영문 'Default Device').

*혼합 유형 선택.* 여러 유형을 함께 선택하면 시스템은 선택 장치가 지원하는 제어의 합집합을 표시한다. 이때 대상 장치 수 카운트는 잠금 해제 계열(장치 잠금 해제·인증 실패 잠금 해제)에만 붙고, 작업 중지·재시작·재연결은 그 제어를 지원하는 장치가 하나라도 있으면 카운트 없이 활성한다. 유형별 제외 규칙은 카운트가 아니라 제어 행의 노출/숨김으로 드러난다 — 어떤 유형도 지원하지 않는 제어 행은 사라진다(예: 마스터·OSDP·확장 모듈 3대 혼합이면 작업 중지·재시작·재연결은 지원 장치 유무로 활성하고, 장치 잠금 해제 행에만 잠긴 장치 수 카운트가 붙는다). 재연결은 상위 장치를 가진 장치(슬레이브·하위 모듈)를 재연결 루트가 아니므로 요청에서 사전 제외하고, 장치에서 서버로 연결하는 장치는 표시하되 비활성으로 두어 요청에서 제외한다. 재연결 가능(루트이면서 서버에서 장치로 연결하는 방식) 장치가 하나라도 있으면 연결 끊김과 무관하게 재연결 버튼을 상시 활성으로 노출한다. 그 외 미지원은 명령을 보낸 뒤 결과에서 귀속한다.

*아무 제어도 지원하지 않는 선택.* 기준은 '한 대라도 받을 수 있으면 활성'이고, 그 반대 경계를 두 단계로 처리한다.

* 제어별로: 선택 장치 중 한 대도 받을 수 없는 제어는 그 행을 숨긴다(비활성으로 남기지 않음). 예를 들어 확장 모듈만 고르면 잠금 해제 계열·재시작·재연결 행이 사라지고 작업 중지 행만 남는다.
* 선택 전체로: 남는 제어 행이 하나도 없으면(예: OSDP 하위 모듈만 선택) 제어 카드 자체를 숨긴다. 대신 안내 문구와 선택 장치 목록 표만 보인다. 권한이 없을 때와 같은 화면이며, 안내 문구는 '선택한 장치 유형은 일괄 제어를 지원하지 않습니다'처럼 쓴다.
* 단, 마스터처럼 제어를 폭넓게 지원하는 장치를 함께 고르면 그 장치 기준으로 제어 행이 다시 나타나고, 카운트만 낮아진다.

*실행 결과.* 실패가 0건이면 성공 안내(Toast)만 보인다 — 제외된 장치가 있어도 결과 창은 열리지 않는다. 한 건이라도 실패하면 부분·전체 구분 없이 오류 안내와 상세 보기(Show Details) 버튼이 보인다(전체 실패도 상세 보기를 제공한다). 운영자가 상세 보기를 누르면 결과 창이 열린다. 결과 창은 방금 실행한 한 제어(한 번에 한 명령)에 대한 결과만 표시하며, 여러 제어를 한 창에 묶지 않는다 — 각 제어는 자기 처리 경로로 보내는 별도 요청이라 결과도 그 한 제어에 귀속한다. 장치별 결과는 독립적으로 처리해 성공분은 유지하고 실패분만 결과 창에 모은다. 장치 잠금 해제와 인증 실패 잠금 해제는 각각 별도 명령이라 결과 창도 명령별로 보여 준다.

*재연결은 예외 — 항상 성공 안내만.* 재연결 요청은 수락 자체가 성공이다("장치 재연결을 시도합니다"). 실제 연결 끊기→대기→연결의 성공/실패는 요청 응답이 아니라 이후 상태 트리 갱신으로 나타나므로, 재연결 요청은 실패로 귀결되는 응답이 없다. 따라서 재연결은 다른 제어처럼 장치별 성공·실패를 산출하지 않고, 단일·일괄 모두 항상 성공 안내(Toast)만 보이고 상세 결과 창을 열지 않는다. 재연결에서 사전 제외된 장치(슬레이브·서버로 연결하는 장치·상위 장치 보유 장치)가 있어도 실패가 0이라 상세 창은 열리지 않는다. 이는 기존 단일 재연결이 이미 성공(시도) 안내로 처리되어 온 동작을 일괄에도 그대로 적용한 것이다.

*결과 창 표시 — 성공·실패·제외 세 그룹.* 결과 창은 장치를 성공·실패·제외(대상 아님) 세 그룹으로만 보여 준다. 각 장치는 제외 → 성공 → 실패 순으로 판정되어 정확히 한 그룹에만 속한다(그룹끼리 겹치지 않는다). 세 그룹은 접기 없이 함께 펼쳐 보이며, 좌열에 성공과 제외(성공 아래에 이어 붙임)를, 우열에 실패를 배치한다. 각 그룹은 개수를 같은 형식의 카운트 배지로 표시한다. 목록이 길면 결과 창 본문 전체가 세로로 스크롤된다.

* *제외(대상 아님, Skipped)* — 명령을 보낼 대상이 아니어서 명령이 전달되지 않은 장치. 두 갈래를 함께 담는다 — 그 제어의 대상에서 사전 제외된 장치와, 잠금 해제 계열에서 원래 잠기지 않아 바꿀 게 없던 장치. 이 그룹은 Skipped(N) 배지와 장치 목록만 보이고 세부 제외 사유는 표기하지 않는다. 결과 창에서 사유를 다는 것은 실패 항목뿐이다(사유 표기는 실패 전용). 제외 판정 근거는 어느 장치를 이 그룹에 넣을지 정할 때만 쓰고 화면에 드러내지 않는다. 운영자는 명령이 가지 않은 장치를 결과 창 한 곳에서 확인한다. 제외 장치가 없으면 이 그룹을 표시하지 않는다.
* *성공(Success)* — 성공 응답 코드를 받은 장치.
* *실패(Fail)* — 실제 오류 코드(동기화 오류 등)를 받은 장치를 사유와 함께 표시한다. 아직 결과가 확인되지 않은 장치도 별도 '보류' 그룹 없이 이 실패 그룹에 '결과 미확인(응답 없음/응답 시간 초과)' 사유로 함께 보인다 — 결과 미확인은 세 경우 전부다: 요청한 장치가 응답에 없거나, 응답 코드가 시간 초과(코드 4)이거나, 응답 코드가 비어 있는(값 없음) 경우. 시스템이 시간 초과를 코드 4 와 빈 값 두 가지로 표기하므로 셋을 하나의 감지 계약으로 함께 다룬다(어느 하나만 처리하면 결과 미확인 장치가 성공으로 잘못 분류된다).

요청 목록에 없던 장치의 응답이 섞여 오면 집계에 넣지 않아 성공·실패·총계가 어긋나지 않게 한다(장치 상태 트리 제어는 요청·응답의 장치가 일치해 정상 흐름에서는 생기지 않는 방어 규칙).

*결과 창 제목·버튼.* 결과 창 제목은 '일부 \[제어명\] 실패(\[실패 수\]/\[전체 대상 수\])' 형식이고(예: '일부 장치 잠금 해제 실패(12/17)' = 17건 중 12건 실패), 경고 문구는 '일부 \[제어명\] 컨트롤에 실패했습니다.'이다. 앞 숫자는 실패 건수다 — 제목이 '실패'를 말하므로 카운트도 실패 기준으로 센다. 전체 대상 수는 성공+실패+제외(대상 아님)로 운영자가 선택한 전체 항목 수이며, 제외 항목도 분모에 포함한다. 한 번에 한 제어만 요청되므로 제목이 제어명을 대표하고, 본문 안에는 제어명 소제목을 따로 두지 않는다. 창 하단에는 두 버튼을 둔다 — 좌측 '실패 목록 클립보드에 복사'는 실패 그룹의 항목(장치명·사유)만 클립보드에 담아 운영자가 실패 목록을 티켓·메일로 옮겨 재시도 대상을 추리게 한다(상시 활성). 우측은 'Okay' 버튼이다. 성공·제외 항목은 복사 대상이 아니다. 전체 실패(성공 0)일 때의 제목·경고 문구 표면형은 아직 확정 전이다(후속 확인).

*실패 사유 표시.* 실패 장치의 사유는 새로 짓지 않고, 장치 응답 코드를 현행 다국어 사전으로 다음 순서에 따라 옮겨 보여 준다 — (1) 장치 오류 전용 사전에 있으면 그 문구, (2) 없고 공통 오류 사전에 있으면 그 문구에 코드를 병기, (3) 어느 사전에도 없는 코드면 '오류 코드: N' 형식으로 표시(사유 칸을 비워 두지 않는다). 장치 오류 코드는 사전 등록 범위보다 넓어 미등록 코드가 흔하므로, 세 번째 코드 표기를 정식 표시 형식으로 둔다. 이 코드→사전 매핑은 상세 결과 창의 장치별 사유용이고, 아래 제어 종류별 결과 메시지 표는 결과 안내(Toast)용이라 서로 섞지 않는다.

제어 종류별 한·영 결과 메시지는 현행 다국어 사전에 등록된 표기를 그대로 쓴다. 장치 잠금 해제 결과는 현행 등록 표기(장치 잠금 해제 성공/실패)를 쓰고, 인증 실패 잠금 해제 결과는 신규 키(Release Lockout)를 쓴다.

|재시작|실패|장치 재부팅 실패|Failed to reboot device.|
|재연결(연결 끊김 후)|성공|장치 재연결을 시도합니다.|Trying to reconnect device.|

|재연결(연결 해제 후)|성공|장치 재연결을 시도합니다.|Trying to reconnect device.|

재연결의 성공 메시지("장치 재연결을 시도합니다")는 요청 수락(시도)을 알리는 성공 안내이고, 위 표의 재연결 실패 메시지("장치 연결 실패"·"장치 연결 해제 실패")는 이후 비동기 재연결 과정에서 개별 장치가 실패했을 때 쓰는 알림용이다 — 일괄 제어의 요청 응답 결과(상세 결과 창)에는 쓰지 않는다.

h3. 2.3 단일 장치 미리보기 제어

* 운영자가 장치를 하나만 선택하면 미리보기 패널에 기존 장치 정보와 함께 기본 제어 버튼(작업 중지·재시작)과 상시 재연결 버튼이 보인다. 장치 정보는 장치 아이디·그룹·연결 상태·모델명·인증 모드·잠김 여부 등이다. 재연결은 연결 끊김과 무관하게 항상 표시·활성되며(정상 연결 장치에서도 설정 재전송·이상 해소 목적), 기본 제어 버튼 행에 둔다. 권한과 장치 유형 조건을 충족하는 버튼만 보이며, 기본 버튼 구성은 장치 유형에 따라 달라진다(마스터·슬레이브=작업 중지·재시작, OSDP·Wiegand=기본 버튼 없음, 확장 모듈=작업 중지만). 상위 장치를 가진 슬레이브·하위 모듈은 재연결 루트가 아니므로 재연결 버튼이 없다.
* 잠김 같은 이상 상태 해소(잠금 해제)는 기본 버튼 행이 아니라 그 상태를 알리는 배너의 버튼으로 처리한다. 기본 버튼 행에는 잠금 해제 버튼이 나타나지 않으므로 정상 장치에는 잠금 해제 버튼이 보이지 않는다. (재연결은 기본 버튼 행에 상시 두고, 끊김 복구 재연결은 아래 배너에서도 별도로 제공한다.)
* 장치 연결이 끊긴 상태에서 서버에서 장치로 연결하는 방식이면 재연결 유도 배너가 보이고, 그 배너 안의 끊김 복구 재연결 액션과 기본 버튼 행의 상시 재연결 버튼이 함께 보일 수 있다(배너 끊김 복구 재연결과 상시 재연결은 차원이 다르다).
* 장치에서 서버로 연결하는 방식(Device▶Server)이면 끊김 유도 배너에 재연결 액션이 없고 안내 문구만 보이며, 단일 미리보기의 기본 버튼 행에도 재연결 버튼을 표시하지 않는다(단일 미리보기는 한 장치만 다루므로 서버가 재연결을 개시할 수 없는 장치에 못 누르는 버튼을 노출하지 않는다). 잠김 상태가 함께 있어도 잠김 표시는 연결 방식과 무관하게 유지한다.
* 단일 미리보기에서 재연결(배너의 끊김 복구 재연결과 기본 버튼 행의 상시 재연결 모두)이 표시·활성되는 조건은 상위 장치가 없는 루트 장치(마스터·기본 장치)이면서 서버에서 장치로 연결하는 방식(Server▶Device)일 때다. 상위 장치를 가진 슬레이브·하위 모듈은 재연결 루트가 아니어서 제외되고, 장치에서 서버로 연결하는 방식(Device▶Server)은 서버가 재연결을 개시할 수 없어 제외된다.
* 연결 끊김과 잠김이 동시면 재연결 배너와 잠금 해제 배너가 각각 별도로 쌓여(stack) 함께 보이며, 각 배너가 자기 이상 상태를 해소한다.
* 미리보기 패널의 연결·잠김·이상 상태 표시와 배너는 상태가 바뀌면 별도 새로고침 없이 실시간으로 갱신된다. 미리보기에서 실행한 제어(장치 잠금 해제·인증 실패 잠금 해제·재연결·재시작·작업 중지)의 결과 상태도 같은 방식으로 패널과 트리에 즉시 반영된다.
* 미리보기의 잠금 해제에도 일괄 패널과 같은 표준 확인 창을 적용한다. 미리보기에서 실행한 제어 결과는 기존 단일 제어 안내 규칙으로 처리하며, 일괄 결과 창은 열지 않는다.

h3. 2.4 공통 — 권한 · 실시간 반영 · 다국어

*권한에 따른 노출.* 모니터링 수정 권한을 가진 운영자에게만 제어 버튼이 보인다. 읽기 권한만 있으면 제어 버튼이 보이지 않는다. 권한 정보가 로드되기 전에는 버튼을 숨기고, 로드된 뒤 수정 권한이면 표시한다. 화면 사용 중 권한이 바뀌면 다음 권한 갱신 시점에 노출을 다시 평가한다. 다중 선택 시 선택 장치 중 한 장치라도 해당 제어를 받을 수 있으면 그 버튼은 활성으로 보인다.

*실시간 상태 반영.* 운영자가 트리에서 연결(Connect)·연결 해제를 하면 그 결과가 별도 새로고침 없이 트리에 바로 반영된다. 다른 운영자가 같은 장치의 연결 상태를 바꾼 경우에도 새로고침 없이 확인한다. 같은 장치가 트리 노드·미리보기 패널·일괄 선택 목록 표에 함께 보이는 동안 연결·잠김·이상 상태가 바뀌면 세 위치를 함께 갱신한다(어느 한 화면만 갱신하고 다른 화면이 낡은 상태로 남지 않는다). 일괄 연결 처리 경로가 준비되기 전에는 장치별 순차 호출로 같은 결과를 내며, 순차 호출의 성공·실패 집계도 일괄 경로와 같은 상세 결과 창으로 모은다. 재연결은 연결 끊기 후 일정 시간 뒤 다시 연결하는 순차 동작이고, 그 중간의 연결 끊김은 장애 끊김과 구분한다.

*명령과 장치 보고 상태가 동시에 도착할 때.* 운영자가 보낸 명령과 장치가 보고하는 연결 상태 이벤트가 거의 동시에 도착하면 현행 동작을 그대로 따른다 — 트리·미리보기 표시는 장치 보고 상태 기준으로 즉시 갱신하고, 명령 진행 표식은 명령 응답으로만 해제하며, 재연결 과도기(연결 끊기→일정 시간→연결)의 일시 끊김을 위한 전용 '재연결 중' 과도 상태는 새로 두지 않는다. 명령 결과 안내와 직후 장치 이벤트로 갱신된 상태가 잠시 어긋나 보일 수 있으나, 최종 표시는 장치 보고 상태로 수렴한다.

*다국어 처리.* 제어 행 카운트·제어 라벨·잠금 해제 확인 창 문구·결과 안내·상세 결과 창의 모든 문구는 다국어 키로 표시하고 화면에 직접 박지 않는다. 카운트의 수량 단위(대/건)와 복수 처리는 각 언어 사전 규칙을 따른다. 다음 문구를 신규 키로 등록한다.

* 인증 실패 잠금 해제(ko='인증 실패 잠금 해제' / en='Release Lockout').
* 기본 장치(ko='기본 장치' / en='Default Device') — 재연결 가능 장치 유형 표면형.
* 강제 적용 카운트 라벨(ko='강제 적용' / en='Override') — 등록만 해 두고 작업 중지 카운트 보류에 따라 이번 버전 화면에는 쓰지 않는다.
* 상세 결과 창의 결과 그룹 라벨 한 종(대상 아님(제외))과 실패 사유 한 종(결과 미확인(응답 없음/응답 시간 초과)). 이 두 문구의 한·영 표면형 세부는 후속 확인 항목으로 기획이 확정한다.

|인증 실패 잠금 해제 신규 API 신설|인증 실패 잠금 해제와 잠금 종류(장치 잠금/인증 실패 잠금) 구분을 위한 신규 API 가 신설된다(신규 API 신설 예정). 장치 잠금 해제는 기존 처리 경로를 쓰고, 인증 실패 잠금 상태 필드·인증 실패 잠금 해제 명령은 신규 API 가 제공한다. 신규 API 준비 전까지는 장치 잠금 해제를 우선 제공하고 인증 실패 잠금 해제는 API 준비 후 활성한다.|
|인증 실패 잠금 원인 처리|인증 실패 잠금은 인증 연속 실패·장치 관리자 비밀번호 오입력 등으로 걸리나, 원인을 구분하지 않고 단일 인증 실패 잠금으로 처리한다.|
|카운트는 잠금 해제 계열 둘만|대상 장치 수 카운트는 장치 잠금 해제(장치 잠금 장치 수)·인증 실패 잠금 해제(인증 실패 잠금 장치 수) 두 행에만 표시하고, 대상 1개 이상이면 활성·0이면 비활성으로 둔다. 두 카운트는 잠금 종류를 구분하는 신규 API 상태로 각각 산출한다. 작업 중지·재시작·재연결 행은 카운트 없이 버튼만 두고 활성/비활성만 가른다.|
|재연결 상시 제어(카운트 없음)|재연결을 연결 끊김 전용 배너 해소에서 상시 제어로 승격한다. 단일 미리보기 기본 버튼 행에 연결 끊김 무관 상시 재연결 버튼을 두고(정상 연결 장치에서도 설정 재전송·이상 해소 목적), 일괄 재연결 행은 카운트 없이 재연결 가능(루트·서버에서 장치로 연결하는 방식) 장치가 1대 이상이면 상시 활성한다(종전 '재연결 가능 장치 수' 카운트 표시는 제거, 활성 조건은 유지). 배너의 끊김 복구 재연결은 유지한다(끊김 시 배너 재연결과 기본 버튼 행 상시 재연결이 함께 보일 수 있음).|
|작업 중지 카운트 보류|작업 중지 행의 강제 적용(Override) 카운트는 이번 버전에서 노출하지 않는다. 강제 적용을 장치 단위로 판정할 실시간 상태 소스가 코드·백엔드에 없기 때문이다. 작업 중지 버튼은 카운트 없이 장치 유형·권한 기준으로 노출하고, 카운트는 백엔드 상태 필드 신설 이후 재개한다.|
|장치 유형별 버튼 분기|통신 방식·확장 모듈·상위 장치 유무에 따른 정적 표시 규칙으로 확정한다. 장치 지원 여부를 별도 조회하지 않고 유형만으로 표시한다. 무선 안테나 모듈은 OSDP 하위 모듈이라 모든 제어를 제외해 제어 버튼이 없다.|
|기본 장치 = 별도 단독 루트 장치 유형|재연결 가능 장치 유형인 '기본 장치(Default Device)'는 마스터(슬레이브를 거느린 RS-485 호스트)와 구분되는 별도의 단독(standalone) 루트 장치 유형이다(슬레이브 없이 서버에 직접 연결). 마스터·기본 장치 둘 다 상위 장치가 없는 루트여서 재연결 가능 조건(루트 + 서버에서 장치로 연결)이 같다. 'Default Device' 영문 표면형은 신규 다국어 키로 등록한다.|
|재연결 연결 방향 분기|서버에서 장치로 연결(Server▶Device)이고 상위 장치가 없는 루트 장치(마스터·기본 장치)이면 재연결 버튼을 표시·활성한다. 장치에서 서버로 연결이면 맥락에 따라 갈린다 — 연결 끊김 배너·단일 미리보기에서는 재연결을 숨기고 안내 문구만 표시하고, 일괄 상시 제어에서만 재연결 버튼을 표시하되 비활성으로 두고 사유 툴팁을 단다.|
|혼합 유형·구조적 미지원 처리|혼합 선택 시 해당 제어를 받을 수 있는 장치에만 명령을 전달한다. 구조적으로 전송 불가한 경우(상위 장치 보유·장치에서 서버로 연결되는 재연결, 권한 없음)는 사전 제외 또는 숨김 처리하고, 전송 가능하나 장치 미지원인 경우는 전송 후 '기능 미지원' 결과로 귀속한다.|
|제어별 결과 메시지|재시작·재연결·작업 중지·장치 잠금 해제의 한·영 성공·실패 문구를 현행 다국어 사전 등록 표기로 확정하고, 인증 실패 잠금 해제는 신규 키(Release Lockout)를 쓴다(결과 메시지 표 참조).|
|부분 성공·전체 실패 처리|장치별로 독립 처리하여 성공분은 유지하고 실패분만 상세 결과 창에 표시한다. 한 건이라도 실패하면 부분·전체 구분 없이 상세 보기를 제공하며, 결과 창은 한 번에 실행한 한 제어만 보여 준다(장치 잠금 해제·인증 실패 잠금 해제는 명령별로 표시).|
|재연결 = 요청 수락 성공 전용|재연결은 요청 수락 자체가 성공("장치 재연결을 시도합니다")이고 실패로 귀결되는 응답이 없다. 실제 연결 성공/실패는 요청 응답이 아니라 이후 상태 트리 갱신으로 나타난다. 따라서 재연결은 장치별 성공·실패를 산출하지 않고 단일·일괄 모두 항상 성공 안내(Toast)만 보이며 상세 결과 창을 열지 않는다. 재연결에서 사전 제외된 장치가 있어도 실패 0이라 상세 창을 열지 않는다.|
|결과 창 표시 — 세 그룹(성공·실패·제외)|상세 결과 창의 표시 그룹은 성공·실패·제외(대상 아님) 셋뿐이다. 각 장치를 제외(사전 제외·비잠금) → 성공 → 실패 순으로 판정해 정확히 한 그룹에만 넣는다(겹침 없음). 세 그룹은 접기 없이 함께 펼쳐 좌열에 성공·제외(성공 아래 이어 붙임), 우열에 실패를 두고 각각 Success·Fail·Skipped 카운트 배지로 표시한다. 목록이 길면 결과 창 본문 전체가 스크롤된다. 별도 '보류(결과 미확인)' 그룹은 두지 않고 실패 그룹에 '결과 미확인' 사유로 귀속하며, 잠금 해제 계열에서 잠기지 않은 장치는 별도 '변경 없음' 그룹 없이 제외 그룹에 함께 담는다. 제외 그룹은 세부 사유를 표기하지 않는다(사유 표기는 실패 전용). 상세 보기는 실패 1건 이상일 때만 제공한다(실패 0건이면 제외 장치가 있어도 성공 안내만). 이 계약을 모니터링 공통 계약으로 승격해 출입문·엘리베이터 일괄 제어도 함께 따른다.|
|결과 창 제목·배치·클립보드 복사|결과 창 제목은 '일부 \[제어명\] 실패(\[실패\]/\[전체\])'(앞 숫자 = 실패 건수)이고 경고 문구는 '일부 \[제어명\] 컨트롤에 실패했습니다.'이다(전체 대상 수 = 성공+실패+제외, 제외 항목도 분모 포함). 한 번에 한 제어만 요청되므로 본문 안 제어명 소제목은 두지 않는다. 제외 그룹은 접기 없이 성공 열 하단에 이어 붙여 표시한다. 창 하단 두 버튼은 좌측 '실패 목록 클립보드에 복사'(실패 항목의 장치명·사유만, 상시 활성)·우측 'Okay'다. 전체 실패(성공 0) 제목 표면형은 후속 확인.|
|결과 미확인 감지 계약|결과 미확인은 세 경우 전부다 — 요청 장치가 응답에 없음, 응답 코드 시간 초과(코드 4), 응답 코드 빈 값. 시스템이 시간 초과를 코드 4 와 빈 값 두 가지로 표기하므로 셋을 하나의 감지 계약으로 다룬다(하나만 처리하면 결과 미확인 장치가 성공으로 오분류). 표시는 별도 그룹 없이 실패 그룹의 '결과 미확인(응답 없음/응답 시간 초과)' 사유로 한다.|
|실패 사유 3단 매핑|실패 사유는 새로 짓지 않고 장치 응답 코드를 사전으로 옮긴다 — (1) 장치 오류 전용 사전, (2) 없으면 공통 오류 사전 문구 + 코드 병기, (3) 미등록 코드는 '오류 코드: N' 형식(사유 칸을 비우지 않음). 이 코드→사전 매핑은 상세 결과 창의 장치별 사유용이고, 제어 종류별 결과 메시지 표는 결과 안내(Toast)용이라 서로 섞지 않는다.|
|잠금 해제 요청 = 잠긴 장치만|두 잠금 해제 요청에는 해당 잠금이 실제로 걸린 장치만 담아 보낸다(제어 행 카운트가 세는 대상 집합과 동일). 잠기지 않은 장치는 요청에 넣지 않는다. 이 장치를 제외로 가르는 판정은 화면이 자체적으로 하며, 응답의 성공과 섞이지 않는다.|
|대상 아님(제외) 장치 결과 표시|선택은 됐으나 요청에서 사전 제외된 장치(일괄 재연결의 상위 장치 보유 슬레이브·하위 모듈·서버로 연결하는 장치, 유형 미지원 장치)를 상세 결과 창에 '대상 아님(제외)' 그룹으로 보인다. 잠금 해제 계열에서 원래 잠기지 않은 장치도 같은 제외 그룹에 함께 담아, 명령이 가지 않은 장치를 결과에서 투명하게 드러낸다. 그룹은 접기 없이 Skipped(N) 배지와 장치 목록만 표시하고 세부 제외 사유는 표기하지 않는다(사유 표기는 실패 전용). 제외 장치가 없으면 그룹을 표시하지 않는다.|
|제어 패널·선택 목록 경계선 — 드래그 리사이즈|일괄 제어 패널에서 제어 버튼 묶음과 선택 목록 표 사이에 구분 경계선을 두어 두 영역을 나눈다(단일 미리보기의 제어 영역·장치 정보 영역 구분과 같은 처리). 운영자는 이 경계선을 위아래로 드래그해 두 영역의 높이 배분을 조절할 수 있다(선택 목록 표 확장 — 모든 일괄 제어 화면 공통).|
|권한 게이트 방식|모니터링 수정 권한자만 제어 버튼을 볼 수 있으며, 조건 미충족 버튼은 비활성이 아닌 숨김으로 처리한다.|
|아무 제어도 지원하지 않는 선택 표시|선택 장치가 한 장도 받을 수 없는 제어 행은 숨긴다. 선택 장치가 지원하는 제어가 한 종도 없으면 제어 카드 대신 안내 문구와 선택 장치 목록만 표시한다(권한 없음과 같은 패턴). 제어를 넓게 지원하는 장치가 함께 선택되면 그 장치 기준으로 행이 다시 노출되고 카운트만 낮아진다.|
|연결 일괄 처리 임시 방식|일괄 연결 처리 경로 준비 전에는 장치별 순차 호출로 동일 결과를 낸다.|
|실시간 상태 반영|미리보기 패널의 장치 상태 표시(연결·잠김·이상)와 일괄 선택 목록 표(연결 표시등·이상 열)를 별도 새로고침 없이 실시간으로 갱신하고, 연결·연결 끊기·제어 결과를 트리·미리보기·선택 목록에 즉시 반영한다.|
|명령·장치 이벤트 동시 발생 시 화면|현행 동작을 그대로 명세화한다. 장치 보고 상태 기준 즉시 갱신, 명령 진행 표식은 명령 응답으로만 해제, 전용 '재연결 중' 과도 상태는 두지 않는다.|

h2. 4. 후속 확인 필요

||후속 확인 항목||모호한 이유||후보 옵션||
|무선 도어록 모니터링 제어 버튼 분기|무선 안테나 모듈은 모든 제어 제외가 확정됐으나, 무선 도어록(Wireless Door Lock)은 현행 코드에 전용 장치 유형이 없고 장치 관리 화면에서만 다뤄져 모니터링 트리에서 어떤 제어를 노출/제외하는지 정의돼 있지 않다.|(a) 테스트 케이스로 노출 제어를 확인해 장치 유형 표에 행 확정 (b) 무선 도어록은 모니터링 제어 범위 밖으로 명시|
|대량 선택 일괄 제어 질의 한도·성능 (개발)|대량 장치를 다중 선택해 일괄 제어할 때 대상 장치 목록 질의의 항목 수 한도·성능(질의 길이·데이터베이스 한도·타임아웃)을 개발에서 확인해야 한다. UI 동작 규칙이 아니라 구현 의존 항목이다.|(a) 질의를 나누어 배치 호출 (b) 동시 요청 수 제한|
|전부 성공 + 제외 장치만 있을 때의 안내|상세 결과 창은 실패 1건 이상일 때만 열린다. 그래서 모든 장치가 성공하고 요청에서 제외된 장치만 있는 경우, 이 제외 장치를 성공 안내(Toast)에서 어떻게 알릴지가 아직 정해지지 않았다. (결과 창의 세 그룹 표시·제외 그룹 펼침·성공 열 하단 배치·긴 목록 스크롤은 확정됐다. 제외 항목의 세부 사유는 표기하지 않는다 — 사유 표기는 실패 전용이다. 실패 사유 '결과 미확인'과 전체 실패 제목의 한·영 표면형 세부만 함께 확정한다.)|(a) 성공 안내에 '대상 아님 N대' 문구 병기 (b) 병기 없이 성공 안내만(전부 성공 시 제외는 미표시)|

*남은 의존(미결 아님).* 작업 중지의 강제 적용 카운트는 이를 산출할 장치 단위 실시간 상태 소스가 백엔드에 마련되어야 화면에 도입할 수 있다. 이번 버전은 카운트를 보류하고 작업 중지 버튼만 노출하며, 카운트 도입은 백엔드 상태 필드 신설 이후로 미룬다. 인증 실패 잠금 해제는 잠금 종류 구분·인증 실패 잠금 해제 명령을 제공할 신규 API 가 신설될 예정이며(의존이 아니라 예정 작업), 준비 전까지는 장치 잠금 해제를 우선 제공한다.
