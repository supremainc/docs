Assign a separate security level to a user regardless of the biometric 1:N security level set on the device. If a user often fails authentication because the device's 1:N security level is high, lower <Cmd sid='user.fingerSecurityLevel' product='2' /> to reduce authentication failures. 

<Image src='/img/biostarx-new-user-credential-securitylevle.png' />

Set the level in the <Cmd sid='user.fingerSecurityLevel' product='2' /> field. See below for available values.

* <Cmd sid='securityLevel.deviceDefault' product='2' />

* <Cmd sid='securityLevel.lowest' product='2' />

* <Cmd sid='securityLevel.low' product='2' />

* <Cmd sid='securityLevel.normal' product='2' />

* <Cmd sid='securityLevel.high' product='2' />

* <Cmd sid='securityLevel.highest' product='2' />

To save the settings, click <Cmd sid='user.save' product='2' /> in the upper-right corner of the screen.

:::info

* In the <Cmd sid="common.credential" product='2' /> section, if <Cmd sid='user.authMode.privateMode' product='2' /> is set to <Cmd sid="user.authMode.biometric" product='2' />, the input user cannot be identified and the 1:1 security level does not apply; it applies only when the mode includes a card or ID. For more information about <Cmd sid='user.authMode.privateMode' product='2' />, see <DocLink docId='platform/biostar_x/enroll-credential-authmode' />.

* Set an appropriate security level. A higher security level may result in lower fingerprint authentication rates or a higher [false rejection rate (FRR)](../../reference/glossary#frr).

:::
