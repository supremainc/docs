Monitor the status of doors, elevators, and advanced access control in real time to operate the security system reliably. Use the status icons in <Cmd sid='shell.header.arena' /> to check alarms and abnormal statuses at a glance and respond immediately to entries that require action.

On the <Cmd sid='shell.header.launcher' /> page, click <Cmd sid='shell.header.arena' />, or select <Cmd sid='shell.header.arena' /> from the shortcut list in the upper-left corner of the screen. Check the status of each entry in the <Cmd sid='arena.tree.door.title' /> tab in the left sidebar.

## Before you start

Make sure the devices connected to the door are set up correctly. Make sure the device is connected to the network and updated to the latest firmware. If an issue occurs, first check the device power status and network connection status.

:::info

* For more information about adding and configuring devices, see <DocLink docId='platform/biostar_x/settings-manage-devices' />.

* For more information about adding and configuring doors, see <DocLink docId='platform/biostar_x/settings-manage-door' />.

* The <Cmd sid='setting.server.logUploadType' product='2' /> feature must be enabled to monitor or control the door status. Turn on this feature in the <Cmd sid='common.general' product='2' /> section under <Cmd sid='shell.header.setting' /> → <Cmd sid='setting.menu.system.root' /> → <Cmd sid='setting.menu.server.server' />.

* The feature to connect cameras to doors through the VMS server is available as an add-on option with an **Essential** or higher license. For more information about licensing policies, see <DocLink docId='platform/biostar_x/licensing#features-add-ons' />.

:::

### Check alarms in the preview panel {/* #check-alarm-in-preview */}

In the <Cmd sid='arena.eventTable.door' /> tab, select a door, elevator, or advanced access control entry with an alarm (<IcAlert width='20px' height='20px' />) icon. Review alarm details at the top of the preview panel in the right pane. For doors and elevators, the top of the panel also shows abnormal (<IcErr width='20px' height='20px' />) status.

<Image src='/img/biostarx-monitoring-door-alarm-banner.png' />

A banner at the top of the panel shows current status details, such as the alarm name and occurrence time, and provides buttons to run appropriate actions.

:::info

* Even if multiple alarms occur at the same time, the banner shows only the most recent alarm.

* For doors or elevators, alarms that occur while the device is disconnected show only the alarm type, without a timestamp.

* The buttons on the banner vary by alarm type, and clicking a button lets you take the appropriate action for the alarm.

* Door control features, such as locking and unlocking, remain available while an alarm appears. For more information about door control, see <DocLink docId='platform/biostar_x/control-door' />.

:::

### Attention criteria {/* #check-the-attention-criteria */}

#### Door

A door requires attention if any condition below applies.

##### Door mode change

This includes doors locked or unlocked by an administrator, a schedule, or an emergency.

<div className='overflow-x'>

| Reason | Status indicator |
| --- | --- |
| Manual operation by an administrator | <Cmd sid='arena.preview.door.operatorLocked' /> / <Cmd sid='arena.preview.door.operatorUnlocked' /> |
| Schedule | <Cmd sid='arena.preview.door.scheduleLocked' /> / <Cmd sid='arena.preview.door.scheduleUnlocked' /> |
| Emergency | <Cmd sid='arena.preview.door.emergencyLocked' /> / <Cmd sid='arena.preview.door.emergencyUnlocked' /> |

</div>

##### Alarm

If any alarm remains uncleared, the system marks it as requiring attention. Forced open, door held open, and anti-passback alarms are classified as alarms, not abnormal statuses.

<div className='overflow-x'>

| Alarm type | Description |
| --- | --- |
| Door forced open | Door forced open without unlocking |
| Door held open too long | Door remains open longer than the set time |
| Anti-passback (APB) alarm | Anti-passback rule violated |
| Timed anti-passback alarm | Time-based anti-passback rule violated |
| Lock Override alarm | Unlocked by Lock Override card authentication while locked (locked by an administrator or by schedule lock) |
| AI video analytics alarm | Video analytics-based alarms, such as tailgating, loitering, intrusion, falls, and abandoned objects |

</div>

##### Abnormal status

The system determines it based on the connection status of devices connected to the door.

<div className='overflow-x'>

| Abnormal status type | Description |
| --- | --- |
| Disconnected | The device is disconnected from the network |
| Synchronization error | Connected, but data is out of sync |
| Multi Communications Server error | An error has occurred on the device's Multi Communications Server |

</div>

:::info

* The <Cmd sid='arena.tree.door.entitiesNeedAttention' /> filter includes device lock and lockout due to consecutive authentication failures (Auth Fail Lockout), in addition to the abnormal statuses above.

* If an alarm and an abnormal status occur together, both icons appear in one row without one covering the other. 

* Abnormal statuses from child devices roll up to the parent door node, so the hierarchy shows where the issue occurs even when the filter is on.

:::

#### Elevator

Elevators are evaluated under the same conditions as doors. However, abnormal status and alarm conditions differ as follows.

* **Mode change**: Same as doors. The system marks the elevator as needing attention when an administrator, schedule, or emergency locks or unlocks it.

* **Abnormal status**: Uses the same criteria as doors. However, elevators do not have forced open or held-open-too-long status, so they are excluded from evaluation.

* **Alarm**: Elevators have dedicated alarms that differ from door alarms. See below.

  <div className='overflow-x'>

  | Alarm type | Description |
  | --- | --- |
  | Elevator alarm triggered | Elevator alarm active |
  | Elevator input alarm | Alarm triggered by an external input signal |
  | Elevator all-floor unlock alarm | All floors forcibly unlocked |

  </div>

:::info

* Floors appear as independent nodes under the elevator node, and each floor has only locked (<IcElevClose />) or unlocked (<IcElevOpen />) status. 

* Alarms and abnormal statuses appear on the parent elevator node, not on floors. When the elevator expands, only floors that require action appear, and normal floors are hidden.

:::

#### Advanced access control

Entries in the advanced access control group (anti-passback, fire alarm, intrusion, muster, occupancy limit, and interlock) are also included when determining whether action is required. However, unlike doors or elevators, mode changes and abnormal status criteria do not apply, and it shows as requiring action if any alarm remains uncleared.

<div className='overflow-x'>

| Alarm type | Description |
| --- | --- |
| Anti-passback (APB) alarm | Anti-passback rule violated |
| Fire Alarm | Alarm triggered by detecting a fire |
| Schedule lock alarm | Alarm triggered while schedule lock is set |
| Intrusion alarm | Alarm triggered by intrusion detection |
| Interlock alarm | Interlock rule violation |
| Muster alarm | Alarm triggered during a muster event |

</div>

:::info

* Armed status and disabled entries are not shown as requiring action. This is because Armed means the security system is operating normally, and Disabled means it is intentionally turned off.

* Each entry appears directly under the advanced access control group, and doors do not expand under it. Only entries that require action remain in the tree, and if none do, the advanced access control group is removed from the tree.

:::

## Expand or collapse the group list

A top-level group or subgroup lets you expand or collapse the list. 

<Image src='/img/biostarx-monitoring-group-expand-collapse.png' />

### Top-level group

1. In the <Cmd sid='arena.tree.door.title' /> tab, select <Cmd sid='arena.tree.door.allDoorGroups' />, <Cmd sid='arena.tree.door.allElevatorGroups' />, or <Cmd sid='arena.tree.door.allZones' />, and then right-click.

2. Choose <Cmd sid='arena.tree.expandAll' /> or <Cmd sid='arena.tree.collapseAll' /> from the pop-up menu. 

All sublists expand or collapse based on the selected top-level group.

### Subgroup

1. To expand or collapse the subgroup list in each top-level group, select the subgroup and right-click. 

2. Select <Cmd sid='arena.tree.contextMenu.expandBelow' /> or <Cmd sid='arena.tree.contextMenu.collapseBelow' /> option from the pop-up menu. 

The list for the selected subgroup expands or collapses.
