:::tip

Learn what you need to know before getting started with **BioStar X**. **BioStar X** supports 64-bit operating systems. Check the system requirements of the PC before you install **BioStar X**, and then install it.

:::

## Pre-installation notes {/* #before */}

Before installing **BioStar X**, check the following and proceed with the installation.

* **BioStar X** can only be installed on a 64-bit operating system.

* If you are using MS SQL 2012 Express, install [Service Pack 3](https://www.microsoft.com/download/details.aspx?id=49996).

* If you are using MS SQL 2014 Express, install [Service Pack 2](https://www.microsoft.com/en-us/download/details.aspx?id=53168).

* If you are using MS SQL Server, set the `Collation` option for the server and each table to CI (Case-insensitive).

* When you back up a database from an earlier version of **BioStar X**, disable all services before you proceed. Also, back up and restore the AC database and the TA database together, or you cannot use the TA database.

* To back up the **BioStar X** database, also back up the *enckey* file in the *\Program Files\BioStar X\util* folder and the *system.conf* and *setting.conf* files in the *\Program Files\BioStar X* folder. Otherwise, you cannot use the database.

* For the default values for the ports used by **BioStar X**, see <DocLink docId='platform/biostar_x/service-settings' />. If another program occupies the same port, **BioStar X** may not work properly.

## Check the database {/* #checkdb */}

If you are using a database that you set up yourself, check the following before installing **BioStar X**.

### MariaDB {/* #mariadb */}

1. In the *my.cnf* file, change the options under the `[mysql]` section as follows.

   ```ini title='my.cnf'
   character-set-server=utf8
   collation-server=utf8_unicode_ci
   max_connections = 600
   ```

2. In the *my.cnf* file, add the following options under the `[mysql]` section.

   ```ini title='my.cnf'
   log_bin_trust_function_creators = 1
   group_concat_max_len = 102400
   ```

3. Connect to MariaDB with root privileges, and run the command below.

   ```sql title='SQL'
   GRANT SUPER ON . TO user_id@'localhost' IDENTIFIED BY "password";
   GRANT SUPER ON . TO user_id@'%' IDENTIFIED BY "password";
   ```

### MS SQL Server {/* #ms-sql-server */}

:::info

* Set the `Collation` option for all databases and tables to CI (Case-insensitive).

* Database names can contain only numbers, English letters (case-sensitive), and the special symbols `-` and `_`.

:::

#### Set up ports {/* #port-setting */}

* After you run **SQL Server Configuration Manager**, set the **TCP/IP Protocol** under **Protocols for SQLEXPRESS** to the port number to use.

* Restart the SQL Server service to apply the settings.

#### Create a user and database {/* #create-a-user-and-database */}

1. Log in to **SQL Server Management Studio** with the **sa** account using **SQL Server Authentication**.

2. Right-click **Security**, and then click **New Login**.

3. Enter a name in the **Login name** field, and then select **SQL Server Authentication**.

4. Enter the password to use in the **Password** and **Confirm password** fields, and then clear **Enforce password policy**.

5. Click **OK**.

6. Right-click **Databases**, and then click **New Database**.

7. Enter a name in the **Database name** field.

8. Enter the login name set in step **3** in the **Owner** field.

:::tip

In the **Database Files** section, set the following recommended values. Set **Autogrowth** to a fixed size (MB/GB) rather than a percentage, and avoid very small increments that cause frequent growth events.

<Image src='/img/biostarx-before-start-new-database.png' caption />

#### Small organizations (10 GB or less)

* Data: **Initial Size** 1 to 5 GB, **Autogrowth** 100 to 512 MB

* Log: **Initial Size** 512 MB to 2 GB, **Autogrowth** 100 to 512 MB

* TempDB: **Initial Size** 512 MB to 1 GB

> For example: Data 2 GB (**Autogrowth** 256 MB) / Log 1 GB (**Autogrowth** 128 MB) / TempDB 512 MB

#### Medium organizations (10 to 500 GB)

* Data: **Initial Size** 10 to 50 GB, **Autogrowth** 512 MB to 1 GB

* Log: **Initial Size** 5 to 10 GB, **Autogrowth** 512 MB to 1 GB

* TempDB: **Initial Size** 2 to 8 GB

> For example: Data 20 GB (**Autogrowth** 1 GB) / Log 5 GB (**Autogrowth** 512 MB) / TempDB 4 GB

#### Large organizations (500 GB or more)

* Data: **Initial Size** at least 100 GB, **Autogrowth** 1 to 4 GB

* Log: **Initial Size** 20 to 100 GB, **Autogrowth** 1 to 4 GB

* TempDB: **Initial Size** 8 to 32 GB

> For example: Data 100 GB (**Autogrowth** 2 GB) / Log 50 GB (**Autogrowth** 2 GB) / TempDB 16 GB

:::

:::caution

* Don't set **Autogrowth** to very small increments or set **Maxsize** to **Unlimited**; set appropriate limits based on expected growth, or monitor it.

* In environments with high transaction volume, back up the log regularly to prevent the log file size from increasing.

:::

#### Set up the Windows Authentication database {/* #windows-authentication-database-settings */}

<Steps>
<Step>

##### Preliminary settings {/* #preliminary-setting */}

If you use **Microsoft Windows Active Directory**, complete the prerequisites below before you set up the Windows Authentication database.

1. Log in to **SQL Server Management Studio** with an administrator account.

2. Right-click **Security**, and then click **New Login**.

3. Select **Windows Authentication**, and then click **Search**.

4. Click on the location in the **Select a user or group** window, select the Active Directory path, and click **OK**.

5. Enter the user name in the **Enter object name to select** field, then click **Check Names** \> **OK**.

6. Under **Select a page**, click **Server Roles**.

7. Select **sysadmin** and then click **OK**.

8. Under **Select a page**, click **User Mapping**.

9. Select **ac**, **master**, **ta**, and **ve**, and set **Default Schema** to **dbo**.

10. To save the settings, click **OK**.

</Step>
<Step>

##### Set up MS SQL Windows Authentication with an Active Directory account {/* #settingsforusingmssql */}

1. Run *services.msc*.

2. In the SQL Server database **Properties** \> **Log On** window, select **Specify account**, and then log in with a domain user account.

3. Add port 1433 as an exception in Windows Firewall.

4. Create empty **ac**, **ta**, and **ve** databases in SQL Server using **sysadmin** authentication.

5. Set the domain user to use Windows Authentication for SQL Server, and assign all permissions except **sysadmin** to the **ac**, **ta**, and **ve** databases.

6. In *services.msc*, connect to all services except Local Computer.

7. Set the domain user as an administrator on the local service computer.

8. Connect to MS SQL ODBC.

</Step>
<Step>

##### Set up the database {/* #database-setting */}

1. Run **SQL Server Configuration Manager**, and then click **Client Protocols** under **SQL Native Client**.

2. Select **TCP/IP**, and then check the default port.

3. Under **SQL Server Network Configuration**, click **Protocols for SQL EXPRESS**.

4. Make sure the ODBC port in **TCP/IP** is set to the same value as the default port.

5. Log in to **SQL Server Management Studio** with an administrator account.

6. Click **Security** \> **Logins**, and then double-click **NT AUTHORITY\SYSTEM**.

7. Under **Select a page**, click **Server Roles**.

8. Select **public** and **sysadmin**, then click **OK**.

9. Under **Select a page**, click **User Mapping**.

10. Select the **ac**, **ta**, **ve** database and click **OK** to save.

</Step>

</Steps>
