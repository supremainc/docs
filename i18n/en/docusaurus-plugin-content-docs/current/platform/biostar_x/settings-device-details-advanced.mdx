## Add a master administrator <Badge only>CE products</Badge> {/* #master-administrator */}

The <Cmd sid='device.masterAdmin.title' product='2' /> feature strengthens administrator permissions on the device to improve security and prevent unauthorized access and setting changes. With this feature, you must register a master administrator on a new device, and only the registered master administrator can access the administrator menu and change settings.

In <Cmd sid='device.info.advanced' product='2' /> →  <Cmd sid='device.info.administrator' product='2' />, select and enroll two credential types in the <Cmd sid='device.masterAdmin.title' product='2' /> menu.

<Image src='/img/biostarx-setting-device-adv-admin-master-admin.png' />

The credentials you can enroll in <Cmd sid='device.masterAdmin.title' product='2' /> are as follows.

| Credential type | Maximum enrollments | Conditions |
| --- | :-: | --- |
| Card | Up to 4 | Supports only CSN and Wiegand types, and you cannot enroll duplicates within the same type. |
| Face | Up to 2 | Available only on devices equipped with the same algorithm. |
| Fingerprint | Up to 2 | - |
| PIN | 1 | Enter at least eight digits. |

* To change an enrolled credential, click <IcEdit /> to the right of the credential.

* To delete an enrolled credential, click <IcTrash2 /> to the right of the credential.

:::caution

This feature is available only on **CE products** among **Suprema products that support a user interface through an LCD screen**. For more information about supported devices and firmware versions, see <DocLink docId='how-to/master-admin' />.

:::

:::note

**Enrollment conditions**

* You must enroll at least two types of credentials.

* The same conditions apply to all firmware-upgraded devices that support master administrators.

* All credentials supported by the device can be used as authentication means.

:::

:::info

* This feature is available only on Suprema products that support a user interface through an LCD screen.

* On existing devices with upgraded firmware, the <Cmd sid='device.masterAdmin.title' product='2' /> menu does not appear in **BioStar X** device settings.

* Some devices without the <Cmd sid='device.masterAdmin.title' product='2' /> setting (for example, after a firmware upgrade) can strengthen administrator permissions with the <Cmd sid='device.masterAdmin.twoStepAuth.title' product='2' /> option. Depending on the device, the <Cmd sid='device.masterAdmin.twoStepAuth.title' product='2' /> option may not appear.

* Master administrator credentials are stored separately on the device and managed independently of regular users' PINs. Changing or deleting a user PIN does not affect master administrator credentials.

:::

## Two-step authentication settings {/* #two-step-authentication */}

After upgrading firmware on a global device that does not support <Cmd sid='device.masterAdmin.title' product='2' />, use the <Cmd sid='device.masterAdmin.twoStepAuth.title' product='2' /> option to strengthen administrator permissions and improve device security.

<Image src='/img/biostarx-setting-device-adv-two-step.png' />

If you set the <Cmd sid='device.masterAdmin.twoStepAuth.title' product='2' /> option to <Cmd sid='common.use' product='2' />, administrators must use two or more credential types when they authenticate on the device. For example, if a card and a PIN are both enrolled, an administrator must scan the card and enter the PIN to authenticate successfully.

:::info

* If any administrator has fewer than two types of credentials enrolled, activation fails and an error message appears. Enroll two or more types of credentials for all administrators and try again.

  <Image src='/img/biostarx-setting-device-adv-error-admin.png' />

* Depending on the device, <Cmd sid='device.masterAdmin.twoStepAuth.title' product='2' /> may not appear on the screen even though the previously enabled setting is still active. You cannot disable it in **BioStar X**, so contact <Support />.

:::

:::caution

If an administrator is not set on the device, the following pop-up message will appear. In <Cmd sid='device.info.advanced' product='2' /> → <Cmd sid='device.info.administrator' product='2' />, add administrators for all permissions.

<Image src='/img/biostarx-setting-device-adv-warning-admin.png' />

:::

:::warning

If you turn on <Cmd sid='device.masterAdmin.twoStepAuth.title' product='2' /> and then delete credentials so that every administrator has fewer than two credential types, you cannot access the administrator menu on the device when it cannot connect to **BioStar X**. Therefore, you need to be particularly careful when deleting administrator credentials.

:::

## Add an administrator {/* #administrator */}

The <Cmd sid='device.info.administrator' product='2' /> group lets you manage device administrators by permission level.

<Image src='/img/biostarx-setting-device-edit-advanced-administrator.png' />

To add an administrator by permission level, click <Cmd sid='button.plusAdd' product='2' />. When the user list appears, select the user to add. In the user list, you can also click <IcSearch /> to search for a user.

For the permissions of each level, see below.

<div className='table-fixed'>

| Level | Manage user information | Device Settings |
| --- | :-: | :-: |
| <Cmd sid='device.operatorLevel.all' product='2' /> | ✔️ | ✔️ |
| <Cmd sid='device.operatorLevel.user' product='2' /> | ✔️ | ❌ |
| <Cmd sid='device.operatorLevel.configuration' product='2' /> | ❌ | ✔️ |

</div>

:::info

* Add and manage up to 1,000 administrators. The number of administrators you can add may vary depending on the device firmware version.

* To search for a registered user, click <IcSearch /> in <Cmd sid='device.info.admin.searchTitle' product='2' />.

* **Device Settings** lets you change settings for the screen and sound, network, and RS-485.

* To delete an administrator, click <IcTrash2 /> to the right of the administrator.

* Administrators set on each device do not affect **BioStar X** permissions.

* If a device administrator has a PIN shorter than eight digits on a master administrator-supported device (<Badge only>CE products</Badge>), re-enroll the user's PIN with at least eight digits. For more information about enrolling PINs, see <DocLink docId='platform/biostar_x/enroll-credential-pin' />.

* To change the PIN of a user with <Cmd sid='device.operatorLevel.configuration' product='2' /> permissions to four digits, first remove the user from administrator roles on all devices.

:::

:::caution

If the user being set as a device administrator has fewer than two types of credentials enrolled, an error message appears. Enroll two or more types of credentials for all device administrators and try again.

<Image src='/img/biostarx-setting-device-adv-error-admin.png' />

:::

## Attendance management {/* #attendance-management */}

In the <Cmd sid='device.info.tna' product='2' /> group, change the names of the device's attendance events or set the attendance mode.

<Image src='/img/biostarx-setting-device-edit-advanced-tna.png' />

* <Cmd sid='device.info.tnaMode' product='2' />: Set how attendance events are recorded.

  * <Cmd sid='device.tna.mode.unused' product='2' />: Attendance events are not recorded.

  * <Cmd sid='device.tna.mode.byUser' product='2' />: The user can select an attendance event when authenticating.

  * <Cmd sid='device.tna.mode.bySchedule' product='2' />: Attendance events automatically change based on the schedule you set. Select a schedule to apply to attendance events.

  * <Cmd sid='device.tna.mode.lastChoice' product='2' />: Users can continue using the last attendance event they used.

  * <Cmd sid='device.tna.mode.fixed' product='2' />: Only the selected attendance event can be used. Select the fixed attendance event to use.

* <Cmd sid='device.info.tnaRequired' product='2' />: Set this to require the user to record an attendance event when authenticating.

   :::note

   This option is available when the <Cmd sid='device.info.tnaMode' product='2' /> option is set to <Cmd sid='device.tna.mode.byUser' product='2' />. 

   :::

* <Cmd sid='device.info.tnaEvent' product='2' />: Edit attendance event names or add schedules used when the <Cmd sid='device.info.tnaMode' product='2' /> option is set to <Cmd sid='device.tna.mode.bySchedule' product='2' />.

  * <Cmd sid='device.tna.eventKey' product='2' />: Shows a list of keys you can use to log attendance.

  * <Cmd sid='device.tna.label' product='2' />: Change the attendance event name based on <Cmd sid='device.tna.eventKey' product='2' />.

  * <Cmd sid='device.tna.schedule' product='2' />: Set the schedule for automatic changes when the <Cmd sid='device.info.tnaMode' product='2' /> option is set to <Cmd sid='device.tna.mode.bySchedule' product='2' />.

    <Image src='/img/biostarx-setting-device-edit-advanced-tna-auto.png' />

:::info

* Devices without an LCD screen can use <Cmd sid='device.tna.mode.fixed' product='2' /> or <Cmd sid='device.tna.mode.bySchedule' product='2' /> mode and record a fixed attendance event or a schedule-based one. Supported devices are XPass Q2, XPass 2, XPass D2, BioEntry P2, and BioEntry W2.

* For more information about setting up a new schedule, see <DocLink docId='platform/biostar_x/settings-schedule' />.

* If <Cmd sid='device.info.multiFaceAuth.label' product='2' /> is set to <Cmd sid='common.use' product='2' /> on the device, this device cannot be used for time and attendance management. For more information about <Cmd sid='device.info.multiFaceAuth.label' product='2' />, see <DocLink docId='platform/biostar_x/settings-device-details-auth#faceDetectionSettings' />.

:::

### Play a video on the idle screen {/* #playVideo */}

:::note

The feature to play videos on the idle screen is supported on **BioStation 3 Max** firmware v1.1.0 or later. Prepare the video before sending it to the device.

:::

#### Add a video and transfer it to the device

Set the device to play content on the idle screen.

1. On the <Cmd sid='shell.header.launcher' /> page, click <Cmd sid='shell.header.setting' />.

2. Click <Cmd sid='setting.menu.device.root' /> → <Cmd sid='setting.menu.device.device' /> in the left sidebar.

3. In the device list, click BioStation 3 Max.

4. Go to the <Cmd sid='device.info.advanced' product='2' /> → <Cmd sid='device.info.displaySound' product='2' /> section.

5. In <Cmd sid='device.idle.video.playback' product='2' /> → <Cmd sid='device.info.playVideo' product='2' />, set the option to <Cmd sid='common.use' product='2' />.

   <Image src='/img/biostarx-settings-device-playback-playVideo-enable.png' />

6. Click <Cmd sid='device.idle.video.add' product='2' />.

7. Select the video saved locally.

8. After the video uploads, set <Cmd sid='device.info.videoSchedule' product='2' /> and <Cmd sid='device.info.videoVolume' product='2' />.

   <Image src='/img/biostarx-settings-device-playback-playVideo-upload.png' />

9. To transfer the uploaded video to the device, click <Cmd sid='device.idle.video.transfer' product='2' />.

10. The update progress pop-up appears. Do not close the page until the upload completes.

    <Image src='/img/biostarx-settings-device-playback-playVideo-upload-progress.png' />

11. When the upload complete message appears, click <Cmd sid='button.ok' product='2' />.

    <Image src='/img/biostarx-settings-device-playback-playVideo-upload-complete.png' />

12. To save the changes, click <Cmd sid='button.apply' product='2' /> at the bottom of the screen.

:::info

* Videos play according to the schedule set in <Cmd sid='device.info.videoSchedule' product='2' />, only when <Cmd sid='device.info.playVideo' product='2' /> is set to <Cmd sid='common.use' product='2' /> and at least one video is registered. For schedules that do not meet these conditions, the screen selected in <Cmd sid='device.info.defaultIdleScreen' product='2' /> appears.

* The maximum supported video file size is 200 MB, and the file format is MP4 (H.264). 

* Video file names can be up to 48 characters long. The file name cannot include characters such as a period (`.`), apostrophe (`'`), or backtick (`` ` ``).

* You can add up to three videos. When three videos are added, the <Cmd sid='device.idle.video.add' product='2' /> button is disabled.

* If the device is connected as a slave (via RS-485), you cannot add, delete, or transfer videos.

  * If the master device supports video playback, the slave screen shows the list of videos added to the master device as read-only. The list is read-only, and you can add, delete, transfer, or reorder videos only on the master device.

  * If the master device does not support video playback, the slave screen shows only <Cmd sid='device.info.defaultIdleScreen' product='2' />.

:::

:::tip

Use <Cmd sid='button.batchEdit' product='2' /> to add and transfer videos to multiple devices at once. For more information about the <Cmd sid='button.batchEdit' product='2' /> feature, see <DocLink docId='platform/biostar_x/settings-device-using-functions#batchEdit' />.

<Image src='/img/biostarx-settings-device-playback-playVideo-batch-edit.png' />

:::

## Trigger and action settings {/* #triggerAction */}

In the <Cmd sid='device.info.triggerNAction' product='2' /> group, set triggers and actions for each situation. For example, set all alarms to sound when authentication fails, or disable the device when the RS-485 connection is lost.

You can register triggers and actions by selecting an event, or set custom triggers and actions. Click <IcAdd /> <Cmd sid='common.add' product='2' /> on the right side of the <Cmd sid='device.info.triggerNAction' product='2' /> group.

<Image src='/img/biostarx-setting-device-edit-advanced-triggernaction.png' />

### <Cmd sid='triggerAction.trigger' product='2' /> {/* #triggerAction */}

Select a predefined event or add a custom condition.

* <Cmd sid='triggerAction.event' product='2' />: Select a predefined event.

* <Cmd sid='triggerAction.input' product='2' />: Set custom conditions by selecting each entry under the option.

* <Cmd sid='triggerAction.break_glass' product='2' />: Set custom conditions by selecting each entry under the option. Set it to detect input only, without a separate action for the input.

:::info

* When <Cmd sid='triggerAction.trigger' product='2' /> is set to <Cmd sid='triggerAction.event' product='2' />, you can select only one event from the event list.

* When you select <Cmd sid='triggerAction.input' product='2' /> or <Cmd sid='triggerAction.break_glass' product='2' /> to set custom conditions, if the schedule you need is not available, click <Cmd sid='button.plusAddSchedule' product='2' />. For more information about schedule settings, see <DocLink docId='platform/biostar_x/settings-schedule' />.

* When you select <Cmd sid='triggerAction.break_glass' product='2' /> to set custom conditions, if the event name you need is not available, click <Cmd sid='triggerAction.addNewBreakGlassEvent' product='2' />. When this event occurs, the event name you set appears in the event log and real-time log.

* The event name can be up to 64 characters long.

:::

### <Cmd sid='triggerAction.action' product='2' /> {/* #triggeraction */}

Select a predefined action or add a custom action.

:::info

* When you select <Cmd sid='triggerAction.output' product='2' /> to set custom actions, if the signal setting you need is not available, click <Cmd sid='common.addSignal' product='2' /> to set one.

* If you set <Cmd sid='triggerAction.trigger' product='2' /> to <Cmd sid='triggerAction.break_glass' product='2' />, you can set <Cmd sid='triggerAction.action' product='2' /> to <Cmd sid='triggerAction.portNone' product='2' />.

:::

## Security tamper settings {/* #tamper-settings */}

If a tamper event occurs on the device, you can set the device to delete all user information, logs, and security keys stored on the device. To turn on the <Cmd sid='device.info.tamperOn' product='2' /> feature, set it to <Cmd sid='device.info.tamperOn.on' product='2' />.

<Image src='/img/biostarx-setting-device-edit-advanced-tamper.png' />

## Analog intercom settings {/* #analog-intercom-settings */}

Set whether to use an analog intercom. To use the intercom connected to the device, click <Cmd sid='common.use' product='2' /> in the <Cmd sid='device.intercom.title' product='2' /> group.

:::info

This feature is supported only on the BioStation 2 model.

:::

## Camera settings {/* #camera-settings */}

Set the camera frequency. If you set the frequency incorrectly in an environment with fluorescent lights, images may flicker. In the <Cmd sid='device.info.camera' product='2' /> group, set the frequency for your region.

:::info

* This feature is supported by the FaceStation F2 and BioStation A2 models with firmware v2.1.4 or later.

* Camera frequencies vary by geographic location. The USA typically uses 60 Hz, while most other regions use 50 Hz. For the camera frequency in your area, contact your dealer.

:::
