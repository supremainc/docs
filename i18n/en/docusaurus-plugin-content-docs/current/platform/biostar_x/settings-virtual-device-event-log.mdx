With the virtual device feature, you can record events such as clock-in and clock-out from mobile apps or third-party services directly in **BioStar X** when you integrate with Time & Attendance. You can systematically manage event logs without a physical device, which is useful for integration with external systems.

## When should you use it?

Use the virtual device event log integration feature in the following situations.

* When you need to centrally manage events from an external attendance management system in **BioStar X**

* When you need to save punch logs from a mobile app or external system directly in **BioStar X** (record clock-in/clock-out events without database integration)

* When you need to send events directly through the **BioStar X** API from a third-party application or service

## Before you start

The **Event Log API** license must be activated. For more information about licensing policies, see <DocLink docId='platform/biostar_x/licensing#features-add-ons' />.

:::info

For more information about applying licenses, see <DocLink docId='platform/biostar_x/settings-license-biostar-x-license' />.

:::

## Register a virtual device

1. On the <Cmd sid='shell.header.launcher' /> page, click <Cmd sid='shell.header.setting' />.

2. Click <Cmd sid='setting.menu.device.root' /> → <Cmd sid='setting.menu.device.device' /> in the left sidebar.

3. In the device list, click <IcMoreW /> in the upper-right corner of the screen, and then select <Cmd sid='device.addVirtualDevice' product='2' />.

   <Image src='/img/biostarx-settings-device-add-virtual-device.png' />

4. When the <Cmd sid='device.addVirtualDevice' product='2' /> screen appears, enter the setting information.

   <Image src='/img/biostarx-settings-device-add-virtual-device-settings.png' />

   * <Cmd sid='device.info.name' product='2' />: Enter the virtual device name.

   * <Cmd sid='device.info.group' product='2' />: Select the group to assign the virtual device to.

   * <Cmd sid='device.info.deviceId' product='2' />: Enter the unique ID for the virtual device. Set it to a value that does not duplicate an existing device ID.

   * <Cmd sid='common.description' product='2' />: Enter a description for the virtual device.

5. Click <Cmd sid='button.apply' product='2' /> in the lower-right corner of the screen to register the virtual device.

:::info

* <Cmd sid='device.info.deviceId' product='2' /> can be set to a value from 100000 to 999999. Set it to a value that does not duplicate an existing Suprema device ID.

* You cannot change the <Cmd sid='device.info.deviceId' product='2' /> value after you create it.

:::

### Manage device groups

Virtual devices can use the device group feature just like regular devices.

* You can place them in the same group as existing devices.

* If you have group permissions, you can grant permissions to virtual devices in that group.

:::info

For more information about device groups, see <DocLink docId='platform/biostar_x/settings-manage-device-group' />.

:::

### Virtual device limitations

* Virtual devices appear only in the following menus.

  * <Cmd sid='shell.header.setting' /> → <Cmd sid='setting.menu.device.root' /> → <Cmd sid='setting.menu.device.device' />

  * View all event logs and preview event logs in the <Cmd sid='shell.header.arena' /> menu

  * View event logs in the <Cmd sid='shell.header.data' /> menu

* Virtual devices cannot use access control features at doors or in <Cmd sid='setting.menu.advancedAc.root' />.

* Virtual devices cannot be specified as devices for <Cmd sid='shell.header.tna' /> settings.

* Virtual devices do not appear in the device list in the left sidebar of the <Cmd sid='shell.header.arena' /> menu.

* Device control features are not available.

* Not included in the device count for the **Multi Communications Server** license.

## Log events via API

### Supported event types

Only the following event types can be logged.

* **Access granted** (`4088`)

* **Access denied** (`6400`)

### API parameters

You must provide the following parameters when logging events.

| Parameter | Description | Required |
| --- | --- | --- |
| `dev_id` | Only registered virtual device IDs are allowed | Yes |
| `evt` | Access Granted or Access Denied | Yes |
| `datetime` | Event occurrence time | Yes |
| `user_id` | User ID | Yes |
| `tna_key` | Only the specified value can be entered | No |

```json title='Request example'
{
    "packet_device_id" : 100003, // required
    "is_virtual_device" : "true", // required
    "events":[ //4088 access granted, 6400 access denied
        {
            "dev_id": 100003, // required
            "evt": 6400, // required
            "datetime": "2025-08-21T14:12:00Z", // required
            "user_id": "2", // required
            "tna_key": "1"
        },
        {
            "dev_id": 100003,
            "evt": 6400,
            "datetime": "2025-08-21T14:13:01Z",
            "user_id": "2",
            "tna_key": "1"
        }
    ]
}
```

```json title='Response example'
{
    "Response": {
        "code": "0",
        "link": "https://support.supremainc.com/en/support/home",
        "message": "Success"
    }
}
```

:::info

* You can log multiple events for a single virtual device at once in a single API call.

* For more information about using the API, see the [BioStar X API](../../developer/bsxapi?api=virtual-device-event-import).

:::

## View event logs

Event logs recorded through the virtual device are available in the menu.

* <Cmd sid='shell.header.arena' />: View and filter all events, and preview events

* <Cmd sid='shell.header.data' />: View and filter all events

:::info

* For more information about viewing events in the <Cmd sid='shell.header.arena' /> menu, see <DocLink docId='platform/biostar_x/monitoring-event' />.

* For more information about the <Cmd sid='shell.header.data' /> menu, see <DocLink docId='platform/biostar_x/data-generate-reports' />.

:::

## Audit trail

When event logs are recorded, an audit trail entry is created as shown in the example below.

```
Access Granted, 2025/08/05 03:37:49, outside the access door on Floor 12, Administrator(1)
```

:::info

* Even if you log events in a batch, a separate audit trail entry is created for each event.

* For more information about <Cmd sid='setting.menu.system.auditTrail' />, see <DocLink docId='platform/biostar_x/settings-system-audit-trail' />.

:::

## Troubleshooting

### If the <Cmd sid='device.addVirtualDevice' product='2' className='normal' /> button is not visible

Make sure the **Event Log API** license is activated.

### If an API call fails

* Make sure the **Event Log API** license is activated.

* Make sure the device ID is for a registered virtual device.

* Make sure the API parameter format is correct.

### If events do not appear

* Make sure the device you used for logging has the correct virtual device ID.

* Make sure the virtual device is selected in the event filter.

* Check the audit trail to make sure no errors occurred when logging events.
