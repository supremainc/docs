You can change settings for the **BioStar X** server basics, user and device management, server matching, system log levels, and face image storage.

1. On the <Cmd sid='shell.header.launcher' /> page, click <Cmd sid='shell.header.setting' />.

2. Click <Cmd sid='setting.menu.system.root' /> → <Cmd sid="setting.menu.server.server" /> in the left sidebar.

3. Set the options you need in each section.

   * <Cmd sid='common.general' product='2' />: Sets the IP address, port number, session timeout, event log upload method, and log retention period.

   * <Cmd sid='setting.server.userDeviceManagement' product='2' />: Changes user and device management settings.

   * <Cmd sid='setting.server.logLevelManagement' product='2' />: Changes system log level settings.

   * <Cmd sid='settings.expertSettings.title' product='2' />: Sets whether to store both the face image and template, or store only the template without the face image.

4. To save the settings, click <Cmd sid='button.apply' product='2' /> in the lower-right corner of the screen.

## Basic information settings {/* #basic-setting */}

In the <Cmd sid='common.general' product='2' /> section, check or set basic information for **BioStar X**.

<Image src='/img/biostarx-settings-server-general.png' className='none' />

* <Cmd sid="setting.server.biostarIPAdress" product='2' />: Shows the server IP address.

* <Cmd sid="setting.server.logUploadType" product='2' />: Select an event log upload method. If real-time communication with the server is difficult, set this to <Cmd sid="common.manual" product='2' />.

* <Cmd sid="setting.server.logRetainDays" product='2' />: The log retention period can be set from 1 to 120 days.

* <Cmd sid="common.sessionTimeout" product='2' />: Set the session timeout. If you are inactive for the set time after you log in to **BioStar X**, you are automatically logged out.

:::info

If you set the <Cmd sid="setting.server.logUploadType" product='2' /> option to <Cmd sid='common.auto' product='2' />, the device automatically uploads its stored event logs when it reconnects to the server.

:::

## User and device management {/* #user-and-device-management */}

In the <Cmd sid='setting.server.userDeviceManagement' product='2' /> section, set synchronization and authentication methods between users and devices.

<Image src='/img/biostarx-settings-server-management.png' className='none' />

### <Cmd sid="setting.server.automaticUserSync" product='2' className='normal' /> {/* #user-sync */}

Select how to synchronize user information between the server and devices in the <Cmd sid="setting.server.automaticUserSync" product='2' /> option. Synchronization includes users' access levels and access groups, so changes to them on the **BioStar X** server automatically apply to the related devices.

* <Cmd sid="setting.server.syncOption.allDevices" product='2' />: User information is automatically synchronized between the server and devices.

* <Cmd sid="setting.server.syncOption.deviceSync" product='2' />: User information on the server is synchronized with all devices registered on the server. However, user information modified on a device is not synchronized to the server, and only user information added on a device is synchronized to the server.

* <Cmd sid="setting.server.syncOption.smartSync" product='2' />: Only devices in an access group with changes are automatically synchronized with the server.

:::info

* If you select the <Cmd sid="setting.server.syncOption.smartSync" product='2' /> option, users stored on a device that are not in an access group cannot be managed on the server. To use this option, click <Cmd sid='shell.header.setting' /> → <Cmd sid='setting.menu.device.root' /> → <Cmd sid='setting.menu.device.device' />, select each device, and click <Cmd sid="device.sync_all" product='2' /> to run synchronization. For more information about the <Cmd sid="device.sync_all" product='2' /> feature, see <DocLink docId='platform/biostar_x/settings-device-using-functions' />.

* Even if you select the <Cmd sid="setting.server.syncOption.smartSync" product='2' /> option, access groups designated for special purposes are synchronized regardless of the device access group, as follows.

  * Dual authentication access group set for devices and elevators

  * Bypass group in the anti-passback settings

  * Bypass group in the scheduled lock settings

  * Unlock authentication access group in the scheduled unlock settings

  * Intrusion alarm group in the intrusion alarm settings 

* Even if you select the <Cmd sid="setting.server.syncOption.smartSync" product='2' /> option, users designated as device administrators are synchronized regardless of the access group.

:::

### <Cmd sid="setting.server.fingerprintTemplateFormat" product='2' className='normal' /> {/* #fingerprint-template-format */}

In the <Cmd sid="setting.server.fingerprintTemplateFormat" product='2' /> option, select the fingerprint template format. Select from the following options.

* <Cmd>SUPREMA</Cmd>: Suprema fingerprint template format. Used when enrolling fingerprints on Suprema devices.

* <Cmd>ISO</Cmd>: ISO international fingerprint template format.

* <Cmd>ANSI378</Cmd>: Fingerprint template format defined by the American National Standards Institute (ANSI).

:::info

If user fingerprint templates remain on the device, you cannot change to a different format.

:::

### <Cmd sid="setting.server.enrollment_device.title" product='2' className='normal' /> {/* #enrollment-device */}

The <Cmd sid="setting.server.enrollment_device.title" product='2' /> option lets you add devices you use often to enroll fingerprints, faces, or cards.

2. When the <Cmd sid='setting.server.enrollment_device.configure.title' product='2' /> window appears, select the checkbox for the device to add in the list.

### <Cmd sid="setting.server.custom_field.title" product='2' className='normal' /> {/* #custom-field */}

The <Cmd sid="setting.server.custom_field.title" product='2' /> option lets you add fields for entering additional user information. The added fields appear on the user information screen.

1. To add a custom user field, click <Cmd sid="button.plusAdd" product='2' />.

2. Enter a name for the custom user field, and select a type.

   <Image src='/img/biostarx-settings-server-management-custome-field.png' />

   * <Cmd sid="setting.server.custom_field.type.numericbox" product='2' />: Enter a value from 0 to 4294967295. Letters are not allowed.

   * <Cmd sid="setting.server.custom_field.type.textbox" product='2' />: Allows entry of up to 32 characters, including numbers and letters.

   * <Cmd sid="setting.server.custom_field.type.combobox" product='2' />: Add up to 20 entries of up to 32 characters, separated by semicolons (;). (for example, Option1;Option2;Option3)

     <Image src='/img/biostarx-settings-server-management-custome-field-select.png' />

   * <Cmd sid='setting.server.custom_field.type.fileupload' product='2' />: Adds a field for file uploads.

     :::note

     * The maximum file size is 1 MB.

     * The file name can be from 1 to 120 characters long.

     * File name requirements: Use alphanumeric characters, underscores (`_`), and hyphens (`-`), and use a period (`.`) to separate the extension.

     * There are no restrictions on file extensions, and uploaded files are encrypted and stored in the database.

     :::

3. To save the added custom user field, click <Cmd sid='button.apply' product='2' /> in the lower-right corner of the screen.

:::info

* To change the order of custom user fields, change the number in the <Cmd sid='setting.server.custom_field.order' product='2' /> column. The field position changes.

* After modifying the custom user fields, click <Cmd sid='button.apply' product='2' /> in the lower-right corner of the screen.

* To delete a custom user field, click <IcTrash2 />. Deleted fields cannot be recovered.

* For more information about registering and editing user information, see <DocLink docId='platform/biostar_x/how-to-guide-user' />.

* User information with custom user fields can be printed on a card. For more information, see <DocLink docId='platform/biostar_x/settings-card-printer#adding-custom-user-fields' />.

:::

### Other settings {/* #other-settings */}

* <Cmd sid="setting.server.eventLogRetainDays" product='2' />: Set the retention period for access control event logs.

  :::info

  The access control event log retention setting applies only to server logs. This setting does not apply to device event logs. If you need to delete device event logs, delete them individually in the <Cmd sid='shell.header.setting' /> → <Cmd sid='setting.menu.device.root' /> → <Cmd sid='setting.menu.device.device' /> menu.

  :::

* <Cmd sid="setting.server.hideCredentialFaces" product='2' />: To protect users' personal information, hide the preview image when you enroll face credentials. When this option is enabled, the preview screen does not appear when you enroll face credentials for a user.

## Set up server matching {/* #servermatching */}

In the <Cmd sid='common.serverMatching' product='2' /> section, you can set up the [server matching](../../reference/glossary#server_matching) feature, which authenticates user information in **BioStar X** instead of on the device.

<Image src='/img/biostarx-settings-server-server-matching.png' className='none' />

* <Cmd sid="setting.server.serverMatching.use" product='2' />: Turn server matching on or off.

* <Cmd sid="setting.server.serverMatching.matchingConcurrencyCount" product='2' />: Set the maximum number of server matching tasks that can run at the same time.

  :::note

  This option may vary depending on the CPU performance of the server PC where **BioStar X** is installed.

  :::

* <Cmd sid='common.fingerPrint' product='2' />

  * <Cmd sid="setting.server.serverMatching.fastMode" product='2' />: Adjust the fingerprint matching speed.

  * <Cmd sid="setting.server.serverMatching.securityLevel" product='2' />: Set the server matching security level for fingerprints. A higher security level increases the false rejection rate (FRR).

* <Cmd sid='common.face' product='2' />

  * <Cmd sid="setting.server.serverMatching.securityLevel" product='2' />: Set the server matching security level for IR face. A higher security level increases the false rejection rate (FRR).

:::info

The <Cmd sid='common.serverMatching' product='2' /> feature is available as an add-on option with an **Essential** license or higher. For more information about the licensing policy, see <DocLink docId='platform/biostar_x/licensing' />.

:::

## Set system log level {/* #systemloglevel */}

In the <Cmd sid='setting.server.logLevelManagement' product='2' /> section, you can set the level of system logs stored in the database.

<Image src='/img/biostarx-settings-server-system-log-level.png' className='none' />

System logs are managed by predefined categories, and log levels are divided into <Cmd sid="setting.server.logLevel.trace" product='2' />, <Cmd sid="setting.server.logLevel.debug" product='2' />, <Cmd sid="setting.server.logLevel.info" product='2' />, <Cmd sid="setting.server.logLevel.warning" product='2' />, and <Cmd sid="setting.server.logLevel.error" product='2' />. A higher level includes all lower-level logs. For example, if you select <Cmd sid="setting.server.logLevel.trace" product='2' />, the system saves all <Cmd sid="setting.server.logLevel.debug" product='2' />, <Cmd sid="setting.server.logLevel.info" product='2' />, <Cmd sid="setting.server.logLevel.warning" product='2' />, and <Cmd sid="setting.server.logLevel.error" product='2' /> logs as well.

## Store face images {/* #storevisualfaceimage */}

When you enroll a face as a credential, you can set whether to store both the actual image and the template, or only the template.

:::note

**Before you begin**

Before enabling the <Cmd sid="settings.expertSettings.enableOptionLabel" product='2' /> option, save any changes you made in the <Cmd sid="setting.menu.server.server" /> menu first. Click <Cmd sid="button.apply" product='2' /> in the lower-right corner of the screen.

:::

1. In the <Cmd sid="settings.expertSettings.title" product='2' /> section, set the <Cmd sid="settings.expertSettings.enableOptionLabel" product='2' /> option to <Cmd sid="common.use" product='2' />.

   <Image src='/img/biostarx-settings-server-expert.png' className='none' />

2. Click <Cmd sid='settings.expertSettings.enableButton' product='2' />.

3. When the <Cmd sid="settings.expertSettings.detail.title" product='2' /> screen appears, set the <Cmd sid="settings.expertSettings.detail.storeVisualFaceImageOptionLabel" product='2' /> option.

   <Image src='/img/biostarx-settings-server-expert2.png' />

   * <Cmd sid="common.use" product='2' />: Default. Stores both the actual image and the template of the face credential.

   * <Cmd sid="common.notUse" product='2' />: Stores only the template and does not store the actual image of the face credential. Read the warning pop-up that appears when you select this option carefully before setting it.

4. To save the settings, click <Cmd sid="button.apply" product='2' />.

:::caution

**Precautions when turning off the <Cmd sid="settings.expertSettings.detail.storeVisualFaceImageOptionLabel" product='2' /> option**

* If you turn off this feature, all stored face images are deleted, and only templates are stored for faces enrolled later.

* You cannot turn off this feature if the enrolled face images do not have both types of templates. For more information about the <Cmd sid='team.menu.faceMigration' /> feature, see <DocLink docId='platform/biostar_x/migration-face' />.

* After you disable this feature, you cannot import a data file from <Cmd sid="menu.dataImport" product='2' /> if it includes invalid face image templates. To resolve the issue, temporarily enable this feature and then import the data file.

:::
