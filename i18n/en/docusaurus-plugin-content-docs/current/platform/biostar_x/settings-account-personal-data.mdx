Leaving credentials active for users who have not accessed doors for a long time, due to resignation or leave, can lead to security threats such as credential misuse or unauthorized access. The auto deactivation feature deactivates users after a set period since their last access, so you can manage accounts securely without manual cleanup. Before users are automatically deactivated, the system sends a pre-notification email to the specified recipients so you have time to review or make exceptions.

On the <Cmd sid='shell.header.launcher' /> page, click <Cmd sid='shell.header.setting' />. Click <Cmd sid='setting.menu.account.root' /> → <Cmd sid='setting.menu.account.privateData' /> in the left sidebar.

<Image src='/img/biostarx-settings-personal-data.png' />

:::info

Only administrators with permission for this menu can access the <Cmd sid='setting.menu.account.root' /> → <Cmd sid='setting.menu.account.privateData' /> menu. To grant an administrator permission for a specific menu, see <DocLink docId='platform/biostar_x/settings-manage-account#addUserPermission' />.

:::

## Set up auto deactivation {/* #enable-auto-deactivation */}

1. In <Cmd sid='setting.personalData.autoDeactivation' />, click the toggle to turn it on.

2. In the <Cmd sid='setting.personalData.applyTarget' /> section, set the targets for auto deactivation.

   <Image src='/img/biostarx-settings-personal-data-enable.png' />

   * To apply the same criteria to all users, turn on <Cmd sid='setting.personalData.basicSettings' /> and enter <Cmd sid='setting.personalData.inactivePeriod' />. Set a value from 1 to 365 days.

   * To apply different criteria to a specific user group, add <Cmd sid='setting.personalData.exceptionGroup' />. For information about how to add them, see <DocLink inner='#exception-group' />.

3. Once you complete the settings, click <Cmd sid='button.apply' product='2' /> at the bottom of the screen.

4. When the confirmation window appears, check the next scheduled date for automatic processing and the number of users scheduled for deactivation, then click <Cmd sid='setting.personalData.saveChanges' />.

   <Image src='/img/biostarx-settings-personal-data-change-confirm.png' caption />

:::info

* In <Cmd sid='setting.personalData.preNotificationEmail' />, set up a pre-notification email to notify the specified recipients before a user is automatically deactivated. For more information, see <DocLink inner='#pre-notification-email' />.

* Turning on the <Cmd sid='setting.personalData.autoDeactivation' /> option does not automatically turn on <Cmd sid='setting.personalData.basicSettings' />. To set up the policy using only <Cmd sid='setting.personalData.exceptionGroup' />, leave <Cmd sid='setting.personalData.basicSettings' /> turned off.

* Auto deactivation is based on the last access authentication time. The system excludes users with no access history or only access history from before user registration.

* If a user meets both <Cmd sid='setting.personalData.basicSettings' /> and <Cmd sid='setting.personalData.exceptionGroup' />, <Cmd sid='setting.personalData.inactivePeriod' /> in <Cmd sid='setting.personalData.exceptionGroup' /> takes precedence. If the user belongs to two or more <Cmd sid='setting.personalData.exceptionGroup' />, the shortest <Cmd sid='setting.personalData.inactivePeriod' /> applies.

* Automatic deactivation runs once a day (at midnight). Setting changes do not apply immediately; they apply from the next processing time and do not affect pre-notification schedules already sent.

* When you turn off the <Cmd sid='setting.personalData.autoDeactivation' /> option, it saves immediately without a confirmation window.

:::

## Apply different criteria by group {/* #exception-group */}

For specific user groups, you can apply a different value than <Cmd sid='setting.personalData.basicSettings' /> for <Cmd sid='setting.personalData.inactivePeriod' />.

### Add group settings

1. In the <Cmd sid='setting.personalData.exceptionGroup' /> list, click <Cmd sid='button.plusAdd' product='2' /> on the right.

   <Image src='/img/biostarx-settings-personal-data-add-btn.png' />

2. When the <Cmd sid='setting.personalData.addGroup' /> window appears, set each field.

   <Image src='/img/biostarx-settings-personal-data-add-group-settings.png' />

   * <Cmd sid='common.name' />: Enter a name that does not duplicate other group settings. Case and leading or trailing spaces do not matter.

   * <Cmd sid='setting.personalData.inactivePeriod' />: Set from 1 to 365 days.

   * <Cmd sid='setting.personalData.userGroup' />: Select the user groups to apply this setting to. Selecting a group also selects its subgroups.

3. After selecting user groups, click <Cmd sid='common.button.confirm' />.

4. To save changes, click <Cmd sid='button.apply' product='2' /> at the bottom of the screen.

5. When the confirmation window appears, check the next scheduled date for automatic processing and the number of users scheduled for deactivation, then click <Cmd sid='setting.personalData.saveChanges' />.

:::info

* In <Cmd sid='setting.personalData.userGroup' />, user groups outside the administrator's permission scope appear disabled so you cannot select them, but they are not hidden from the list. You can expand this group and select subgroups within the permission scope.

* Administrators whose privileges are set to **All users**, or full administrators, have no limits on user group selection. For more information about administrator roles, see <DocLink docId='platform/biostar_x/settings-manage-account' />.

:::

### Edit and delete group settings

<Image src='/img/biostarx-settings-personal-data-group-edit.png' />

* To edit, in the <Cmd sid='setting.personalData.exceptionGroup' /> list, click <IcRepoEdit title='Edit' /> in the row, change the values, and click <Cmd sid='common.button.confirm' />.

* To delete, click <IcTrash title='Delete' /> in the row to delete. When the confirmation message appears, click <Cmd sid='common.button.delete' />.

To save your edits or deletions, click <Cmd sid='button.apply' product='2' /> at the bottom of the screen. When the confirmation window appears, check the next scheduled date for automatic processing and the number of users scheduled for deactivation, then click <Cmd sid='setting.personalData.saveChanges' />.

:::info

* If <Cmd sid='setting.personalData.exceptionGroup' /> includes user groups outside the administrator's permission scope, they remain in the list, but you cannot edit or delete them.

* <Cmd sid='setting.personalData.exceptionGroup' /> takes precedence over <Cmd sid='setting.personalData.basicSettings' />.

* Deleting <Cmd sid='setting.personalData.exceptionGroup' /> does not restore users already deactivated. After deletion, the system switches to another applicable setting (such as <Cmd sid='setting.personalData.basicSettings' />) if available for that user.

:::

## Pre-notification email settings {/* #pre-notification-email */}

You can notify specified recipients by email before a user is automatically deactivated.

1. In the <Cmd sid='setting.personalData.preNotificationEmail' /> option, turn on the toggle.

   <Image src='/img/biostarx-settings-personal-pre-noti-email-settings.png' />

2. Enter a value for <Cmd sid='setting.personalData.preNotificationDeadline' />. The system sends auto-deactivation notification emails for the period you enter. Set the period from 1 to 30 days.

3. In the <Cmd sid='setting.personalData.preNotificationRecipients' /> field, search for and select a user by name, ID, or email, or enter an email address, then press <Kbd>Enter</Kbd>.

   <Image src='/img/biostarx-settings-personal-pre-noti-email-auto-complete.png' />

4. Once you complete the settings, click <Cmd sid='button.apply' product='2' /> at the bottom of the screen.

5. When the confirmation window appears, check the next scheduled date for automatic processing and the number of users scheduled for deactivation, then click <Cmd sid='setting.personalData.saveChanges' />.

:::info

* To use pre-notification emails, set up SMTP settings. For more information, see <DocLink docId='platform/biostar_x/settings-email-setting' />.

* Set <Cmd sid='setting.personalData.preNotificationDeadline' /> shorter than the inactive period in <Cmd sid='setting.personalData.basicSettings' /> and every <Cmd sid='setting.personalData.exceptionGroup' />.

* You can add email addresses not registered in **BioStar X** as recipients.

* The system sends one consolidated email once a day, not separate emails for each user scheduled for deactivation.

* If <Cmd sid='setting.personalData.basicSettings' /> is off and no <Cmd sid='setting.personalData.exceptionGroup' /> exists, turning on only <Cmd sid='setting.personalData.preNotificationEmail' /> leaves no targets, so the system sends no emails.

:::
