Upgrade faces enrolled in an earlier version of **BioStar X** to the latest algorithm to improve recognition performance. The protocol was improved to send only templates, excluding face images, during user synchronization, which greatly reduces synchronization time and prevents privacy-related issues.

## Before you start

Before running the face migration feature, check the following.

:::note

**What is face migration?**

This feature generates two types of face templates from user images already stored on the BioStar X server. To synchronize faces as templates only during user synchronization, run <Cmd sid='team.menu.faceMigration' />.

:::

### Supported devices and firmware versions

For the list of devices that can synchronize faces as templates, see the list below.

* BioStation 3 Max firmware v1.0.0 or later

* BioEntry W3 firmware v1.0.0 or later

* BioStation 3 firmware v1.3.1 or later

* FaceStation F2 firmware v2.2.0 or later

<details>

<summary>**Notice: FaceStation F2 firmware v1.x.x support discontinued**</summary>

**BioStar X** optimized synchronization performance by sending only templates when synchronizing a user's face to a device. Therefore, support for FaceStation F2 v1.x.x firmware, which can extract templates only on the device, is discontinued. If you are currently using FaceStation F2 firmware v1.x.x, upgrade to the latest firmware to use **BioStar X** with FaceStation F2.

Download the latest firmware from the [Suprema Download Center](https://download.supremainc.com/).

</details>

### Notes on face template types

BioStation 3 Max, BioEntry W3, and BioStation 3 use a different face template type from FaceStation F2.

* **NPU type**: BioStation 3 Max, BioEntry W3, BioStation 3

* **GPU type**: FaceStation F2

:::note

* **Synchronization time between devices with different face template types**

  Before you run <Cmd sid='team.menu.faceMigration' />, if you add BioStation 3 Max, BioEntry W3, or BioStation 3 to a FaceStation F2-only environment and synchronize, the template type changes. NPU-type templates are extracted from images, so this may take considerable time depending on the number of faces registered on the server.

* **Recommended: enroll faces in BioStar X**

  If you enroll a face on a device with its **Store Face Image** option turned off, only the template is synchronized to **BioStar X**, so the face cannot be synchronized to devices with a different face template type; therefore, we recommend enrolling faces in **BioStar X**.

:::

### Device-related notes

The user data file exported from **BioStar X** contains only templates without images, so you cannot import the user data file into FaceStation F2 and BioStation 3 running earlier firmware.

Therefore, FaceStation F2 and BioStation 3 can export data files only with the following firmware versions or later.

* FaceStation F2 firmware v2.2.0 or later

* BioStation 3 firmware v1.3.1 or later

:::caution

If you use FaceStation F2 or BioStation 3, consider upgrading to the latest firmware version. Download the latest firmware from the [Suprema Download Center](https://download.supremainc.com/).

:::

## Run face migration

1. On the <Cmd sid='shell.header.launcher' /> page, click <Cmd sid='shell.header.user' />.

2. Select <IcMoreW/> in the upper-right corner of the screen and click <Cmd sid='team.menu.faceMigration' />.

   <Image src='/img/biostarx-user-face-migration.png' />

3. Check the contents of the warning pop-up and click <Cmd sid='common.button.continue' />.

   <Image src='/img/biostarx-user-face-migration-warning.png' width='60%' />

Run face migration. When face migration is complete, a pop-up window appears and shows the total number of faces and the success and failure counts.

* After migration succeeds, sync the user information to the device to apply the changes. For more information about how to transfer user information to the device, see <DocLink docId='platform/biostar_x/transfer-user-info-to-device' />.

* If face migration fails, you can download the list of failed users as a CSV file. To delete all faces that failed migration, click <Cmd sid='common.delete' />.

:::info

* Only the administrator account with user ID **1** can use this feature.

* Don't navigate away from the current page while the migration is in progress.

* Depending on the user, larger enrolled face images may take longer to generate templates.

* For about 1,000 faces, the process takes about 18 minutes, although this may vary depending on server performance.

* For more information about how to store only the template, without saving the user's facial image to the server, see <DocLink docId='platform/biostar_x/settings-server-server#storevisualfaceimage' />.

:::
