Aprenda a agregar y conectar una base de datos secundaria que funcione con Multi Communications Server para reducir la carga en el servidor principal.

:::info

* Para agregar una base de datos secundaria, necesita una licencia de **Multi Communications Server**. Para obtener más información sobre las políticas de licencias, consulte <DocLink docId='platform/biostar_x/licensing#features-add-ons' />.

* Para obtener más información sobre la instalación de Multi Communications Server, consulta <DocLink docId='platform/biostar_x/install-communication-server' />.

:::

## Antes de comenzar

Si usa un dominio o nombre de host en lugar de una dirección IP para la comunicación de base de datos en MariaDB, asegúrese de revisar las indicaciones a continuación.

* Si no usa una dirección IP, es posible que no pueda ejecutar `Create user` o `Grant`.

* Si se comunica mediante un dominio o nombre de host, asegúrese de que haya un usuario y permisos registrados para localhost.

* Si instaló BioStar X mediante la instalación Express, la cuenta root está registrada solo para localhost. Además, registre el usuario y los permisos para la dirección IP del servidor o *127.0.0.1*.

### Cómo registrar

Verifique si el usuario root con Host *127.0.0.1* tiene una contraseña; si no, establezca una y otorgue permisos.

1. Verifique si el usuario root con Host *127.0.0.1* tiene una contraseña. 

   ```sql
   SELECT * FROM mysql.user;
   ```

   <Image src='/img/common/biostarx-subdb-mariadb-specific.png' alone />

   Si está en blanco, no hay una contraseña establecida; asegúrese de ejecutar la consulta de la siguiente entrada para agregar una contraseña y otorgar permisos.

2. Establezca una contraseña y otorgue permisos para el usuario root con Host *127.0.0.1*.

   ```sql
   ALTER USER 'root'@'127.0.0.1' IDENTIFIED BY '<Main DB AC Schema Password>';
   GRANT ALL PRIVILEGES ON *.* TO 'root'@'127.0.0.1';
     
   CREATE USER '<Main DB AC User>'@'127.0.0.1' IDENTIFIED BY '<Main DB AC Schema Password>';
   GRANT ALL PRIVILEGES ON *.* TO '<Main DB AC User>'@'127.0.0.1';
   CREATE USER '<Main DB AC User>'@'::1' IDENTIFIED BY '<Main DB AC Schema Password>';
   GRANT ALL PRIVILEGES ON *.* TO '<Main DB AC User>'@'::1';
     
   CREATE USER '<Main DB TA User>'@'127.0.0.1' IDENTIFIED BY '<Main DB AC Schema Password>';
   GRANT ALL PRIVILEGES ON *.* TO '<Main DB TA User>'@'127.0.0.1';
   CREATE USER '<Main DB TA User>'@'::1' IDENTIFIED BY '<Main DB AC Schema Password>';
   GRANT ALL PRIVILEGES ON *.* TO '<Main DB TA User>'@'::1';
     
   CREATE USER '<Main DB VE User>'@'127.0.0.1' IDENTIFIED BY '<Main DB AC Schema Password>';
   GRANT ALL PRIVILEGES ON *.* TO '<Main DB VE User>'@'127.0.0.1';
   CREATE USER '<Main DB VE User>'@'::1' IDENTIFIED BY '<Main DB AC Schema Password>';
   GRANT ALL PRIVILEGES ON *.* TO '<Main DB VE User>'@'::1';
     
   FLUSH PRIVILEGES;
   ```

   ```sql title='Example'
   ALTER USER 'root'@'127.0.0.1' IDENTIFIED BY 'admin1234!';
   GRANT ALL PRIVILEGES ON *.* TO 'root'@'127.0.0.1';
   FLUSH PRIVILEGES;
   ```

### Configurar la comunicación por dirección IP

Use la siguiente configuración para forzar la comunicación por dirección IP.

1. Después de instalar **BioStar X**, vaya a la siguiente ruta.

   >  C:\Program Files\BioStar X\ta\mariadb-11.4.4-winx64

2. Abra el archivo *my.cnf* con privilegios de administrador y agregue la opción `skip-name-resolve` a la sección [mysqld].

   ```ini
   [mysqld]
   port = 3312
   character-set-server=utf8
   collation-server=utf8_unicode_ci
   socket = /tmp/mysql.sock
   skip-external-locking
   key_buffer_size = 32M
   max_allowed_packet = 64M
   ...
   skip-name-resolve
   ```

3. Reinicia el servicio de MariaDB.

## Agregar una base de datos secundaria {/* #add-sub-db */}

Aprenda a agregar una base de datos secundaria. Según el tipo de base de datos, use uno de dos métodos: MariaDB o SQL Server.

### MariaDB {/* #mariadb */}

<Steps>
<Step>

#### Base de datos principal

Cree una cuenta y otorgue permisos para que la nueva base de datos secundaria pueda acceder a la base de datos principal.

```sql
CREATE USER '<Main DB AC Schema User>'@'<Sub DB IP>' IDENTIFIED BY '<Main DB AC Schema Password>';

GRANT ALL PRIVILEGES ON <Main DB AC Schema>.* TO '<Main DB AC Schema User>'@'<Sub DB IP>';
FLUSH PRIVILEGES;
```

```sql title='Example'
CREATE USER 'biostarx_ac_user'@'192.168.12.42' IDENTIFIED BY 'password';

GRANT ALL PRIVILEGES ON biostar2_ac.* TO 'biostarx_ac_user'@'192.168.12.42';
FLUSH PRIVILEGES;
```

</Step>
<Step>

#### Base de datos secundaria

Cree una cuenta y otorgue permisos para que la base de datos principal pueda acceder a la nueva base de datos secundaria.

```sql
CREATE USER '<Sub DB AC Schema User>'@'<Main DB IP>' IDENTIFIED BY '<Sub DB AC Schema Password>';

GRANT ALL PRIVILEGES ON <Sub DB AC Schema>.* TO '<Sub DB AC Schema User>'@'<Main DB IP>';
FLUSH PRIVILEGES;
```

```sql title='Example'
CREATE USER 'biostarx_ac_user'@'192.168.12.161' IDENTIFIED BY 'password';

GRANT ALL PRIVILEGES ON biostar2_ac.* TO 'biostarx_ac_user'@'192.168.12.161';
FLUSH PRIVILEGES;
```

</Step>
<Step>

#### Verifique si FederatedX está habilitado

En las bases de datos principal y secundaria, ejecute el siguiente comando para comprobar si el motor de almacenamiento FederatedX está habilitado.

```sql
SHOW ENGINES;
```

Si el resultado de la consulta muestra `Engine : FEDERATED, Support : YES`, ya está instalado. Si el motor de almacenamiento FederatedX no está instalado, ejecute la siguiente consulta.

```sql
INSTALL PLUGIN federated SONAME 'ha_federatedx';
```

:::info

Compruebe si el archivo *ha_federatedx.dll* existe en la carpeta *lib/plugin* dentro de la ruta donde está instalada MariaDB. Normalmente, el archivo dll se encuentra en *C:\Program Files\MariaDB \{version}\lib\plugin*.

:::

</Step>
<Step>

#### Registrar un alias de servidor

Registre un alias de servidor para que la tabla federatedX creada en la base de datos secundaria pueda acceder a la tabla de origen en la base de datos principal.

```sql
CREATE SERVER 'default' FOREIGN DATA WRAPPER mysql OPTIONS (HOST '<Main DB IP>', PORT <Main DB PORT>, DATABASE '<Main DB AC Schema>', USER '<Main DB AC USER>', PASSWORD '<Main DB AC USER Password>');

-- Confirm registration
SELECT * FROM mysql.servers;
```

Para cambiar la información de Host, Port, DB, User o Password de un nombre de servidor registrado, modifíquela mediante una instrucción `Alter`. También puede cambiar solo parte de la información.

```sql
ALTER SERVER 'default' OPTIONS (HOST '<Main DB IP>', PORT <Main DB PORT>, DATABASE '<Main DB AC Schema>', USER '<Main DB AC USER>', PASSWORD '<Main DB AC USER Password>');
```

```sql title='Example'
CREATE SERVER 'default' FOREIGN DATA WRAPPER mysql OPTIONS (HOST '192.168.12.161', PORT 3312, DATABASE 'biostar2_ac', USER 'biostarx_ac_user', PASSWORD 'password');
  
ALTER SERVER 'default' OPTIONS (HOST '192.168.12.161', PORT 3312, DATABASE 'biostar2_ac', USER 'biostarx_ac_usermt__fttid__', PASSWORD 'password');
```

</Step>
<Step>

#### Configurar enlaces de tablas

Siga los pasos a continuación para vincular las tablas necesarias de la base de datos secundaria con las tablas de la base de datos principal.

* La siguiente consulta genera sentencias `CREATE TABLE` en la base de datos principal.

  ```sql
  select
    concat(
        'CREATE TABLE IF NOT EXISTS <SubDB_AC_Database_Schema>.', table_name,
        ' ENGINE=FEDERATED ',
        'CONNECTION=''default/', table_name, ''';'
    ) as create_table_sql
  from information_schema.TABLES
  where TABLE_SCHEMA = '<MainDB_AC_Database_Schema>'
      AND TABLE_TYPE = 'BASE TABLE'
      AND NOT TABLE_NAME REGEXP '^t_lg[0-9]{6}$'
      AND NOT TABLE_NAME REGEXP '^t_almevt[0-9]{6}$'
      AND NOT TABLE_NAME REGEXP '^t_lgalmtrstrc[0-9]{6}$'
  ORDER BY TABLE_NAME;
  ```

  :::info

  Debido a la naturaleza de FederatedX, establezca `Table_type` en 'BASE TABLE'. El `VIEW type` también funciona, pero no se recomienda.

  :::

* Asegúrese de ingresar en la base de datos secundaria la sentencia `CREATE` generada por la consulta anterior.

</div>

</Step>
<Step>

#### Configurar Service Manager

1. Ejecuta **BioStar X Service Manager**. (<Start /> → **BioStar X** → **BioStar X Service Manager**)

2. Haz clic en el menú <Cmd>DATABASE</Cmd> en la barra lateral izquierda.

3. Haga clic en <Cmd>+ Add Database</Cmd> en la esquina superior derecha de la pantalla.

4. En la pantalla Add Database, ingrese cada campo.

   <Image src='/img/common/biostarx-subdb-sm-add-database.png' alone />

   * <Cmd>Name</Cmd>: Ingresa el nombre de la base de datos.

   * <Cmd>Description</Cmd>: Ingresa la descripción de la base de datos.

   * <Cmd>DB Type</Cmd>: Selecciona el tipo de base de datos. (Maria, MS SQL)

   * <Cmd>Host</Cmd>: Ingresa el nombre de host o la dirección IP del servidor de bases de datos.

   * <Cmd>Port</Cmd>: Ingresa el número de puerto del servidor de bases de datos.

   * <Cmd>AC</Cmd> / <Cmd>TA</Cmd>: Ingrese el nombre, el usuario y la contraseña de las bases de datos AC y TA.

5. Haga clic en <Cmd>Test Connection</Cmd> en la esquina superior derecha para comprobar si la base de datos está conectada correctamente.

6. Para guardar la configuración, haga clic en <Cmd>Save</Cmd> en la esquina superior derecha de la pantalla.

</Step>
</Steps>

### SQL Server {/* #sqlserver */}

<Steps>
<Step>

#### Otorgar permisos para la base de datos principal

Con una cuenta con privilegios de sysadmin, otorgue los siguientes permisos en la base de datos principal.

```sql
GRANT ALTER ANY LINKED SERVER TO [<MAIN DATABASE AC USER>];
GRANT ALTER ANY LOGIN TO [<MAIN DATABASE AC USER>];
```

```sql title='Example'
GRANT ALTER ANY LINKED SERVER TO [biostar_x_user];
GRANT ALTER ANY LOGIN TO [biostar_x_user];
```

</Step>
<Step>

#### Otorgar permisos para la base de datos secundaria

1. se requieren privilegios de sysadmin para configurar User Mapping para las tablas y los usuarios en la base de datos secundaria. Luego, agregue el rol `db_owner`.

   <Image src='/img/common/biostarx-subdb-user-mapping.png' alone />

2. Otorgue los siguientes permisos a la base de datos que agregue.

   ```sql
   GRANT ALTER ANY LINKED SERVER TO [<SUB DATABASE AC USER>];
   GRANT ALTER ANY LOGIN TO [<SUB DATABASE AC USER>];
   ```

   ```sql title='Example'
   GRANT ALTER ANY LINKED SERVER TO [biostar_x_user_sub];
   GRANT ALTER ANY LOGIN TO [biostar_x_user_sub];
   ```

   * <Cmd>Host</Cmd>: Ingresa el nombre de host o la dirección IP del servidor de bases de datos.

   * <Cmd>Port</Cmd>: Ingresa el número de puerto del servidor de bases de datos.

6. Para guardar la configuración, haga clic en <Cmd>Save</Cmd> en la esquina superior derecha de la pantalla.

:::info

* Una vez completada la configuración, la configuración de Linked Server se aplica automáticamente a las bases de datos principal y secundaria.

* Cuando edita la información de la base de datos, la configuración de Linked Server cambia automáticamente. Cuando edita la base de datos principal, la información actualizada se aplica a la configuración de Linked Server de todas las bases de datos secundarias registradas. Cuando edita una base de datos secundaria, la información actualizada se aplica solo a la base de datos principal y a esa base de datos secundaria.

:::

</Step>
<Step>

#### Generar una consulta de Linked Temp Table

Ejecute la siguiente consulta en la base de datos principal para generar una consulta de Linked Temp Table que se ejecutará en la base de datos secundaria.

```sql
USE [<AC Schema>];
GO
DECLARE @LinkedServer  sysname = N'default';
DECLARE @SourceSchema  sysname = N'dbo';
DECLARE @TargetSchema  sysname = N'dbo';
 
SELECT
    'IF OBJECT_ID(N''' + QUOTENAME(@TargetSchema,'') + '.' + QUOTENAME(t.name,'') + ''', ''SN'') IS NOT NULL '
  + 'DROP SYNONYM ' + QUOTENAME(@TargetSchema) + '.' + QUOTENAME(t.name) + ';'
  + 'CREATE SYNONYM ' + QUOTENAME(@TargetSchema) + '.' + QUOTENAME(t.name)
  + ' FOR ' + QUOTENAME(@LinkedServer) + '.' + QUOTENAME(DB_NAME()) + '.' + QUOTENAME(s.name) + '.' + QUOTENAME(t.name) + ';'
  AS recreate_synonym_sql
FROM sys.tables AS t
JOIN sys.schemas AS s
  ON s.schema_id = t.schema_id
WHERE s.name = @SourceSchema
  AND t.is_ms_shipped = 0
  AND t.name NOT LIKE 't_lg[0-9][0-9][0-9][0-9][0-9][0-9]'
  AND t.name NOT LIKE 't_almevt[0-9][0-9][0-9][0-9][0-9][0-9]'
  AND t.name NOT LIKE 't_lgalmtrstrc[0-9][0-9][0-9][0-9][0-9][0-9]'
ORDER BY t.name;
```

```sql title='Example'
-- Example
USE [main_ac_x_215];
GO
DECLARE @LinkedServer  sysname = N'default';  -- Linked Server name set in the sub DB
DECLARE @SourceSchema  sysname = N'dbo';      -- Schema to target in the main DB
DECLARE @TargetSchema  sysname = N'dbo';      -- Schema to create synonyms in the sub DB (reflected in the output string)

SELECT
    'IF OBJECT_ID(N''' + QUOTENAME(@TargetSchema,'') + '.' + QUOTENAME(t.name,'') + ''', ''SN'') IS NOT NULL '
  + 'DROP SYNONYM ' + QUOTENAME(@TargetSchema) + '.' + QUOTENAME(t.name) + ';'
  + 'CREATE SYNONYM ' + QUOTENAME(@TargetSchema) + '.' + QUOTENAME(t.name)
  + ' FOR ' + QUOTENAME(@LinkedServer) + '.' + QUOTENAME(DB_NAME()) + '.' + QUOTENAME(s.name) + '.' + QUOTENAME(t.name) + ';'
  AS recreate_synonym_sql
FROM sys.tables AS t
JOIN sys.schemas AS s
  ON s.schema_id = t.schema_id
WHERE s.name = @SourceSchema
  AND t.is_ms_shipped = 0
  AND t.name NOT LIKE 't_lg[0-9][0-9][0-9][0-9][0-9][0-9]'
  AND t.name NOT LIKE 't_almevt[0-9][0-9][0-9][0-9][0-9][0-9]'
  AND t.name NOT LIKE 't_lgalmtrstrc[0-9][0-9][0-9][0-9][0-9][0-9]'
ORDER BY t.name;
```
