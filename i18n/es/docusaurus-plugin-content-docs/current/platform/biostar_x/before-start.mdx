:::tip

Conozca lo que necesita saber antes de comenzar con **BioStar X**. **BioStar X** es compatible con sistemas operativos de 64 bits. Verifique los requisitos del sistema de la PC antes de instalar **BioStar X** y, luego, instálelo.

:::

## Notas previas a la instalación {/* #before */}

Antes de instalar **BioStar X**, verifique lo siguiente y continúe con la instalación.

* **BioStar X** solo se puede instalar en un sistema operativo de 64 bits.

* Si está utilizando MS SQL 2012 Express, instale el [Service Pack 3](https://www.microsoft.com/download/details.aspx?id=49996).

* Si está utilizando MS SQL 2014 Express, instale el [Service Pack 2](https://www.microsoft.com/en-us/download/details.aspx?id=53168).

* Si está utilizando MS SQL Server, configure la opción `Collation` del servidor y de cada tabla a CI (sin distinción de mayúsculas y minúsculas).

* Cuando haga una copia de seguridad de una base de datos de una versión anterior de **BioStar X**, desactive todos los servicios antes de continuar. Además, haga una copia de seguridad y restaure las bases de datos AC y TA juntas, o no podrá usar la base de datos TA.

* Para hacer una copia de seguridad de la base de datos de **BioStar X**, haga una copia de seguridad también del archivo *enckey* en la carpeta *\Program Files\BioStar X\util* y de los archivos *system.conf* y *setting.conf* en la carpeta *\Program Files\BioStar X*. De lo contrario, no podrá usar la base de datos.

* Para ver los valores predeterminados de los puertos utilizados por **BioStar X**, consulte <DocLink docId='platform/biostar_x/service-settings' />. Si otro programa ocupa el mismo puerto, **BioStar X** podría no funcionar correctamente.

## Verificar la base de datos {/* #checkdb */}

Si está utilizando una base de datos que configuró usted mismo, verifique lo siguiente antes de instalar **BioStar X**.

### MariaDB {/* #mariadb */}

1. En el archivo *my.cnf*, cambie las opciones en la sección `[mysql]` de la siguiente manera.

   ```ini title='my.cnf'
   character-set-server=utf8
   collation-server=utf8_unicode_ci
   max_connections = 600
   ```

2. En el archivo *my.cnf*, agregue las siguientes opciones en la sección `[mysql]`.

   ```ini title='my.cnf'
   log_bin_trust_function_creators = 1
   group_concat_max_len = 102400
   ```

3. Conéctese a MariaDB con privilegios de root y ejecute el siguiente comando.

   ```sql title='SQL'
   GRANT SUPER ON . TO user_id@'localhost' IDENTIFIED BY "password";
   GRANT SUPER ON . TO user_id@'%' IDENTIFIED BY "password";
   ```

### MS SQL Server {/* #ms-sql-server */}

:::info

* Configure la opción `Collation` para todas las bases de datos y tablas a CI (sin distinción de mayúsculas y minúsculas).

* Los nombres de base de datos solo pueden contener números, letras en inglés (distinguiendo mayúsculas y minúsculas) y los símbolos especiales `-` y `_`.

:::

#### Configurar puertos {/* #port-setting */}

* Después de ejecutar **SQL Server Configuration Manager**, configure **TCP/IP Protocol** en **Protocols for SQLEXPRESS** con el número de puerto que se utilizará.

* Reinicie el servicio de SQL Server para aplicar la configuración.

#### Crear un usuario y una base de datos {/* #create-a-user-and-database */}

1. Inicie sesión en **SQL Server Management Studio** con la cuenta **sa** usando **SQL Server Authentication**.

2. Haga clic derecho en **Security** y, luego, haga clic en **New Login**.

3. Ingrese un nombre en el campo **Login name** y, luego, seleccione **SQL Server Authentication**.

4. Ingrese la contraseña que va a usar en los campos **Password** y **Confirm password**, y luego desmarque **Enforce password policy**.

5. Haga clic en **OK**.

6. Haga clic con el botón derecho en **Databases** y luego haga clic en **New Database**.

7. Ingrese un nombre en el campo **Database name**.

8. Ingrese el nombre de inicio de sesión configurado en el paso **3** en el campo **Owner**.

:::tip

En la sección **Database Files**, configure los siguientes valores recomendados. Configure **Autogrowth** con un tamaño fijo (MB/GB) en lugar de un porcentaje y evite incrementos muy pequeños que provoquen eventos de crecimiento frecuentes.

<Image src='/img/biostarx-before-start-new-database.png' caption />

#### Organizaciones pequeñas (10 GB o menos)

* Datos: **Initial Size** de 1 a 5 GB, **Autogrowth** de 100 a 512 MB

* Registro: **Initial Size** de 512 MB a 2 GB, **Autogrowth** de 100 a 512 MB

* TempDB: **Initial Size** de 512 MB a 1 GB

> Por ejemplo: Datos 2 GB (**Autogrowth** 256 MB) / Registro 1 GB (**Autogrowth** 128 MB) / TempDB 512 MB

#### Organizaciones medianas (de 10 a 500 GB)

* Datos: **Initial Size** de 10 a 50 GB, **Autogrowth** de 512 MB a 1 GB

* Registro: **Initial Size** de 5 a 10 GB, **Autogrowth** de 512 MB a 1 GB

* TempDB: **Initial Size** de 2 a 8 GB

> Por ejemplo: Datos 20 GB (**Autogrowth** 1 GB) / Registro 5 GB (**Autogrowth** 512 MB) / TempDB 4 GB

#### Organizaciones grandes (500 GB o más)

* Datos: **Initial Size** de al menos 100 GB, **Autogrowth** de 1 a 4 GB

* Registro: **Initial Size** de 20 a 100 GB, **Autogrowth** de 1 a 4 GB

* TempDB: **Initial Size** de 8 a 32 GB

> Por ejemplo: Datos 100 GB (**Autogrowth** 2 GB) / Registro 50 GB (**Autogrowth** 2 GB) / TempDB 16 GB

:::

:::caution

* No configure **Autogrowth** con incrementos muy pequeños ni configure **Maxsize** como **Unlimited**; establezca límites adecuados según el crecimiento previsto o supervise el crecimiento.

* En entornos con un alto volumen de transacciones, haga copias de seguridad del registro de forma regular para evitar que aumente el tamaño del archivo de registro.

:::

#### Configure la base de datos de autenticación de Windows {/* #windows-authentication-database-settings */}

<Steps>
<Step>

##### Ajustes previos {/* #preliminary-setting */}

Si utiliza **Microsoft Windows Active Directory**, complete los requisitos previos a continuación antes de configurar la base de datos de autenticación de Windows.

1. Inicie sesión en **SQL Server Management Studio** con una cuenta de administrador.

2. Haga clic derecho en **Security** y, luego, haga clic en **New Login**.

3. Seleccione **Windows Authentication** y, a continuación, haga clic en **Search**.

4. En la ventana **Select a user or group**, haga clic en Ubicación, seleccione la ruta de Active Directory y haga clic en **OK**.

5. Ingrese el nombre de usuario en el campo **Enter object name to select**, luego haga clic en **Check Names** > **OK**.

6. En **Select a page**, haga clic en **Server Roles**.

7. Seleccione **sysadmin** y luego haga clic en **OK**.

8. En **Select a page**, haga clic en **User Mapping**.

9. Seleccione **ac**, **master**, **ta** y **ve**, y establezca **Default Schema** en **dbo**.

10. Para guardar la configuración, haga clic en **OK**.

</Step>
<Step>

##### Configurar la autenticación de Windows de MS SQL con una cuenta de Active Directory {/* #settingsforusingmssql */}

1. Ejecuta *services.msc*.

2. En la ventana **Properties** \> **Log On** de la base de datos de SQL Server, seleccione **Specify account** y luego inicie sesión con una cuenta de usuario de dominio.

3. Agregue el puerto 1433 como una excepción en Windows Firewall.

4. Cree bases de datos vacías **ac**, **ta** y **ve** en SQL Server mediante autenticación **sysadmin**.

5. Configure al usuario de dominio para que use Windows Authentication para SQL Server y asigne todos los permisos, excepto **sysadmin**, a las bases de datos **ac**, **ta** y **ve**.

6. En *services.msc*, conéctese a todos los servicios excepto Local Computer.

7. Establece al usuario de dominio como administrador en el equipo de servicio local.

8. Conéctate a MS SQL ODBC.

</Step>
<Step>

##### Configurar la base de datos {/* #database-setting */}

1. Ejecute **SQL Server Configuration Manager** y luego haga clic en **Client Protocols** en **SQL Native Client**.

2. Seleccione **TCP/IP** y luego verifique el puerto predeterminado.

3. En **SQL Server Network Configuration**, haga clic en **Protocols for SQL EXPRESS**.

4. Asegúrese de que el puerto ODBC en **TCP/IP** esté configurado con el mismo valor que el puerto predeterminado.

5. Inicie sesión en **SQL Server Management Studio** con una cuenta de administrador.

6. Haga clic en **Security** \> **Logins** y luego haga doble clic en **NT AUTHORITY\SYSTEM**.

7. En **Select a page**, haga clic en **Server Roles**.

8. Selecciona **public** y **sysadmin**, luego haz clic en **OK**.

9. En **Select a page**, haga clic en **User Mapping**.

10. Selecciona las bases de datos **ac**, **ta**, **ve** y haz clic en **OK** para guardar.

</Step>

</Steps>
