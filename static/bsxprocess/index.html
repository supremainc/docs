5. Revision Note 프로세스

5-1. RN 범위 설정

BSS가 JIRA 필터를 통해 해당 릴리스의 신규 기능, 기능 개선, 버그 픽스를 모두 정리한다. QES가 버그별 RN 공개 여부를 작성한 후, PM이 리뷰하여 확정하는 구조. RN 범위는 W-4에 1차(잠정) 확정하고, 테스트 종료 시점(W-1)에 최종 재확정한다 (5-4 참조).

#단계활동담당
5-1-11차 정리JIRA 필터로 신규 기능/개선/버그 픽스 전체 목록 정리 + 누락 검토BSS
5-1-2공개 여부버그별 RN 공개 여부 작성QES

5-2. 버그 픽스 영향도 태그 기준

QES 기존 분류체계에 아래 기준을 병합하여 운영한다. 별도의 새로운 태그 체계를 만들지 않는다.

#태그기준RN 반영예시
5-2-1A — 고객 체감기본 동작 변경, UI 변화, 기존 워크플로우 영향PM이 개별 검토 → RN 포함 여부 결정로그인 실패 수정, 이벤트 누락 수정
5-2-2B — 특정 조건특정 설정/환경에서만 발생, 엣지 케이스RN에 한 줄 요약으로 묶음 ("기타 안정성 개선 XX건")특정 디바이스 조합 싱크 오류
5-2-3C — 내부/미미고객이 인지하기 어려운 수정, 내부 로직RN에서 제외로그 포맷 변경, 메모리 최적화

RN 범위 확정 시 제외 항목은 JIRA에 "RN 제외" 태그로 이력을 관리한다.

수가 적을 때도 동일 구조를 유지한다. 일관된 프로세스가 모두의 부담을 줄인다.

5-3. 사내 베타 빌드 이후 변경 발생 시 커뮤니케이션

사내 베타 빌드(W-4) 전달 이후 버그 픽스로 인한 변경이 발생하는 경우, BSS 개발 담당자가 TSS TW에 직접 공유한다.

  • 이력 관리: JIRA 이슈 코멘트 병행 (추적용)
  • 타이밍: 변경 발생 즉시
  • 내용: 변경된 동작, 영향받는 매뉴얼/RN 항목, 스크린샷 재촬영 필요 여부

5-4. RN 최종 확정 (테스트 종료, W-1)

W-4 RN 범위 확정은 그 시점의 이슈 리스트 기준 1차(잠정) 확정이다. 테스트 과정에서 이슈가 추가·제외·변경될 수 있으므로, QES가 테스트를 마무리하는 W-1에 RN 반영 이슈를 최종 판단하여 확정한다.

  • W-3 내부 온보딩 트레이닝(Webinar)은 Suprema 내부 대상이며, 여기서 공유하는 Revision Note는 잠정본(프리뷰)이다. 테스트 결과에 따라 조정될 수 있다.
  • W-1에 QES가 테스트 종료 후 최종 반영 이슈를 판단 → PM이 반영 여부를 결정하고 최종 승인 → 최종 RN 확정.
  • 고객·파트너 대상 최종 RN은 W0 릴리스와 함께 배포한다.
  • 근거: 테스트 종료 전에는 RN 반영 이슈가 유동적. 확정을 W-4에 고정하면 테스트 중 발생한 변경(버그 재분류, must-fix 추가/제외 등)이 RN에 반영되지 못한다.
적용 조건. 테스트 기간이 RN 공개(W-3) 이후까지 이어지는 릴리스에 적용한다. 테스트가 W-3 전에 끝나면 1차 확정이 곧 최종 확정이다.

6. 매뉴얼 업데이트 프로세스

6-1. 범위 설정

BSS가 JIRA 필터로 신규 기능/기능 개선 목록을 정리하고 누락 여부를 검토한다. 이후 XPS가 고객 사용 시나리오 관점에서 최종 검토하며, 검토를 마친 목록은 BSS가 TSS TW에 공유한다.

6-2. TSS TW 작업 시작 전제조건 — 사내 베타 빌드 (W-4)

TSS TW가 매뉴얼 초안 작성을 시작하려면 사내 베타 빌드가 전달되어야 한다.

사내 베타 빌드 정의 (Suprema 내부):

  • 모든 신규 기능 포함 (기능 누락 없음)
  • QES가 본격 QA 테스트를 시작할 수 있는 상태
  • 이후 변경은 버그 픽스만 (신규 기능 추가 없음)
TSS TW가 겪는 핵심 문제는 빌드 전달 이후에도 변경과 버그 수정이 계속 발생하여 작성 내용이 무효화되는 것. 사내 베타 빌드 이후 버그 픽스로 인한 변경이 발생하면 BSS 개발 담당자가 TSS TW에 즉시 공유한다 (5-3 참조).

6-3. 매뉴얼 초안 기술 확인 (W-2)

TSS TW가 사내 베타 빌드 기반으로 작성한 매뉴얼 초안을 BSS 개발 담당자가 기술 정확성(동작 절차, 설정값, API) 관점에서 확인한다.

  • 범위: 신규/변경 기능 관련 섹션 한정
  • 타이밍: W-2, PM 최종 검토(W-1) 전 완료
  • W-1 PM 최종 검토는 시장 메시지/고객 경험 관점, 기술 정확성은 본 단계에서 확보

7. Known Issues 합동 회의

릴리스 W-2~W-1 시점에 Known Issues를 전체적으로 검토하고 대응 방향을 협의하는 회의.

참석: XPS (PM) + BSS + QES + TSS

목적:

  • QES가 정리한 Known Issues 리스트 전체 검토
  • 각 이슈별 대응 방향 협의: 릴리스 전 수정 / Known Issue로 문서화 / 다음 버전으로 이관
  • RN 및 매뉴얼에 반영할 Known Issues 범위 확정
  • 고객 커뮤니케이션 방향 합의

8. 제품 출시 미팅

릴리스 직전(W-1) 전체 출시 준비 상태를 점검하는 미팅. 기존 제품등록 미팅을 확장하여 출시 프로세스 전반을 다룬다.

참석: XPS (PM) + BSS + QES + TSS
